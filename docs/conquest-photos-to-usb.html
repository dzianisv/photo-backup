Method 1: SnapDisk (one tap, background copy)

SnapDisk is a free Android app that does exactly this job and nothing else. Install it from the v0.1.2 APK (it's not on Google Play yet), then:

  1. Plug in the USB drive. It mounts on plug-in on most Android phones with USB host support — look for a "USB storage added" notification. If nothing appears, check Settings > Storage for the drive. OTG support is unconfirmed in the sources I found on every Conquest model that can run SnapDisk — the S10, the S12, the S12 Pro, the S16, the S22 5G, and the EX201 — so the drive mounting is the test itself: if it appears in Settings > Storage, the phone hosts drives and the rest of this method works; if it never appears, the phone does not host drives and Method 4 is the route. The S6, the S8, the S8+, and the S8 Pro run Android 5.1 or 6.0, below SnapDisk's Android 7.0 minimum, so SnapDisk cannot run on those four at all — and the S9's Android version is disputed, so check Settings > About phone on that model first.
  2. Open SnapDisk and check the folders. The app opens to a settings screen with a From folder and a To folder, each with a folder picker. The defaults are already right for most people: From /sdcard/DCIM (your camera photos — Conquest camera photos live in DCIM/Camera), To /disk/DCIM on the drive. If your photos live somewhere else, tap the From picker and choose that folder — the picker is the Android system folder picker, and the app keeps access to it.
  3. Tap Backup. SnapDisk offers a backup in a notification when the drive connects: "External storage is connected. Backup photos?" Tap it and your whole library copies oldest-first — your earliest photos first — in the background, while you use the phone normally. The copy mirrors the source folder structure on the drive, so DCIM stays DCIM.
  4. Watch the progress notification — real percent, copied / total size, speed, and time left — with Pause and Stop. You can pause and resume any time.
  5. Wait for "Backup complete." Every file is size-verified after copying, so the counts are proof, not a promise. Files that already copied are never copied twice — so if the free 5 GB per-run limit stops a big library partway, just run it again and it picks up where it left off.

The copies are the original files. SnapDisk streams each file byte-for-byte from the phone to the drive — the code reads the file and writes the same bytes out, with no decode, no recompression, and no resize — and then checks that the copy on the drive is the same size as the original. Other apps copy originals byte-for-byte too; what SnapDisk adds is the automated whole-library run: oldest-first order, progress with Pause and Stop, resume where it stopped, and skip-if-already-copied on the next run. If a file is corrupt or too big for FAT32, it's retried once, then skipped with its reason listed — it never stalls the whole backup. The free version backs up manually, up to 5 GB per backup run, with no ads, no account, and no cloud. SnapDisk Pro is a one-time $9.99 purchase (no subscription) that starts the backup automatically when you plug in a disk and removes the size limit. The app has no internet permission, so your photos physically cannot leave your device.

Method 2: a file manager (the stock route, no app needed)

A file manager can copy your photos to the USB drive — the YouTube guides' route is an OTG connection with the built-in file manager, and askfilo's route is the same, and either is the manual route for external storage: 1. Plug in the USB drive — a notification should appear saying "USB storage added"; tap it to open the drive. If nothing appears, check Settings > Storage for the drive. 2. Open the file manager (Files by Google on Conquest phones) and confirm the USB drive shows up under storage devices. 3. Go back to Internal storage, DCIM, Camera, where your camera photos live. 4. Select the photos (long-press the first, tap the rest, or select all). 5. Tap Copy, then select the USB drive, and wait for the copy to finish — don't unplug the drive until the file manager says it's done. Eject the drive from the notification or from Settings > Storage before unplugging it. Use Copy, not Move: Move deletes the originals as it goes, so a bumped cable halfway through loses photos. This works fine for a one-off copy. Its limits are the reason SnapDisk exists: you pick files one by one, there is no progress detail beyond a spinner, no resume if you unplug mid-copy, no verification that every file actually arrived, and you have to repeat the whole manual selection next time photos pile up. For a library that grows every day, the app's oldest-first background copy is the calmer option.

It is a real local copy — but the card stays in the phone, and opening the card anywhere else needs a card reader. 4. A computer copy is the other way to move files off the phone — "connect the Conquest S8 to a computer using the USB cable and make a copy of the files using the file browser", per devicesfaq, and the same advice appears on the S8 KT35A-S8 page. It is a real backup — but it needs a PC in between, and the backup lands on the PC, not on a USB drive as plain files straight from the phone. None of them is a one-tap way to copy your camera roll to a drive. All of them work fine for what they are. Their limit, for photos specifically: none of them gives you a folder of plain photo files on a USB drive you can plug into any computer and open. Method 4: through a computer (if you have one)

If a PC or Mac is handy, the old route still works — and it is the route Conquest's own backup advice names: plug the Conquest phone into the computer with a USB cable, tap the USB notification and choose File transfer — and drag the DCIM folder onto the USB drive. This works fine, and it is the only route above that needs a second device in between. What this does not do

A few honest limits, so the automatic copy is not oversold:

  • Photos and videos only. SnapDisk copies image and video files. Documents, voice notes, and anything that isn't a photo or video is skipped — Google backup is the tool if you want contacts, messages, and settings in the same backup, not just photos.
  • Only the folder you pick. By default that's DCIM — your camera photos. Photos in other folders (Downloads, app folders) only copy if you point the From folder at them, or at a parent folder that contains them.
  • Free 5 GB per run. A library bigger than 5 GB stops at the cap; run it again and it picks up where it stopped. Pro ($9.99, one-time) removes the limit and starts the backup automatically when you plug in a disk.
  • Files over 4 GB on FAT32 are skipped. Very long videos on a FAT32 drive are listed with their reason instead of failing the backup. Reformat the drive to exFAT if you need them.
  • It never deletes. SnapDisk only copies. Freeing space on the phone is copy, check the copy on the drive, then delete the originals yourself — never the other way round.
  • Four Conquest models cannot run SnapDisk at all. The S6 runs Android 5.1, and the S8, the S8+, and the S8 Pro run Android 6.0, below SnapDisk's Android 7.0 minimum — so SnapDisk cannot install on any of the four, even though the S8 lists OTG support. Their photos move off the phone by file manager or computer copy instead.
  • The S9's Android version is disputed. devicesfaq lists the S9 as Android 5.1.1 with a Qualcomm Snapdragon 615, while trak.in lists it as Android 7.1.1 with a MediaTek Helio P25 — so check Settings > About phone on that model before installing; if the 5.1.1 source is right, SnapDisk cannot run on it at all.
  • OTG support is unconfirmed on every model that can run SnapDisk. The only Conquest model with an OTG listing in the sources I found is the S8 — FindPare lists "USB OTG: Yes" with micro USB 2.0 — and the S8 runs Android 6.0, so it cannot run SnapDisk. On the S10, the S12, the S12 Pro, the S16, the S22 5G, and the EX201, no source I found mentions OTG at all — so plug a drive in and check Settings > Storage before relying on it. The drive mounting is the test.
  • The USB port type is unconfirmed on the S22 5G and the EX201. The S10 has micro USB — the root guide for it says to connect the phone to a computer using a micro USB cable — and the S12 and the S16 have USB-C, while the S8 has micro USB 2.0. The S22 5G store listing and the EX201 spec sheet I found state no USB port type, so check your own port before buying an adapter.
  • The S6 comes in two variants. The original 2015 S6 has a MediaTek MT6732, 1 GB of RAM, 8 GB of storage, and a 4000 mAh battery per Ubergizmo, while the S6 OCTA has a MediaTek MT6752, 3 GB of RAM, 32 GB of storage, and a 6000 mAh battery per mobilexfiles — but both run Android 5.1, so neither can run SnapDisk.

What to avoid

  • Buying an adapter you don't need — or the wrong one. A USB-C flash drive plugs straight into the S12 and the S16, which have USB-C — so an adapter is only needed for a regular USB-A drive, and it must be a USB-C OTG adapter, not a micro-USB one. The S10 has micro USB instead, so it needs a micro-USB OTG adapter. The S22 5G and the EX201 have no USB port type stated in the sources I found, so check the port first. A plain micro-USB charging cable is not an OTG adapter: it connects the phone to a computer, which is the opposite direction.
  • Mistaking a cloud backup for a photo copy. Google Drive and Google Photos back your phone up to Google's servers — if you want to plug the drive into a computer and open the pictures, you need a plain copy, that is Method 1 or 2, not a cloud backup.
  • Mistaking a PC tool for a phone-to-USB copy. Conquest's own backup advice is a computer copy with a USB cable and a file browser — but it is a copy to a computer, and the backup lands on the PC. If the phone and the drive are all you have, a phone-to-USB copy is the route, not a desktop copy.
  • Mistaking a spec table or a FAQ page for a phone-to-USB guide. The S8 FAQ page and the Conquest spec tables are real Conquest pages — but the FAQ only says to connect the phone to a computer and copy the files with a file browser, and the spec tables only list an Android version, a chipset, or a USB connector type. Neither of them describes copying your camera roll straight to a USB drive from the phone.
  • Mistaking OTG support for SnapDisk support. The S8 lists USB OTG support — FindPare lists "USB OTG: Yes" — but it runs Android 6.0, below SnapDisk's Android 7.0 minimum. OTG lets a file manager copy photos to a drive; it does not make the phone new enough to install SnapDisk. Test with a drive, and use Method 2 or 4 on that model.
  • Mistaking a microSD card copy for a USB backup. Copying DCIM to a microSD card is a real local copy — the S8+ takes a card up to 128 GB, the S10 takes one up to 128 GB, and the S16 takes one up to 128 GB — but the card stays in the phone, and opening it anywhere else needs a card reader; a USB drive plugs into any computer as it is.
  • PC-only tools when you have no computer. Drag-and-drop through a Windows PC works — but it needs the PC in between. If the phone and the drive are all you have, a phone-to-USB copy is the route — that is the gap this article fills, as of November 18, 2026.
  • Cloud backup dressed as USB backup. If the app needs an account and an upload before your photos are safe, that's a cloud subscription with a USB step. Your photos sit on someone else's server, and the backup stops working the day you stop paying. On Conquest the cloud routes are Google Photos and Google Drive — and Google Photos' "Storage saver" setting compresses photos, which is the one place quality actually gets lost.
  • Installing SnapDisk on a Conquest phone that cannot run it. The S6 runs Android 5.1, and the S8, the S8+, and the S8 Pro run Android 6.0 — SnapDisk needs Android 7.0 or later and cannot install on any of the four. Check Settings > About phone before installing; every other Conquest model I found runs Android 7.1, 8.1, 9.0, 11, or 12, except the S9, whose Android version is disputed.
  • Deleting before verifying. A backup is only a backup once you've confirmed the copy. Copy, open a few photos on the drive, then delete from the phone — never the other way round. SnapDisk only copies — it never deletes — so the delete step is always yours, and always after the check.
  • Moving instead of copying. The file manager's Move option copies and then deletes the originals in one step. If the copy fails halfway, photos are already gone from the phone. Copy first, verify, then delete.
  • Unplugging mid-copy. Pulling a USB drive out while files are still writing can corrupt the file in flight. Wait for the copy to finish, or pause it first — SnapDisk's Stop button exists for exactly this.

Rule of thumb: if you have to pick the files yourself, it isn't a backup — it's a chore you will skip. Automate the copy, check it on the drive, then delete from the phone.
