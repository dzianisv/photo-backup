Method 2: a file manager (the stock route, no app needed)

A file manager can copy your photos to the USB drive — the YouTube guides' route is an OTG connection with the built-in file manager, and askfilo's route is the same, and either is the manual route for external storage: 1. Plug in the USB drive — a notification should appear saying "USB storage added"; tap it to open the drive. If nothing appears, check Settings > Storage for the drive. 2. Open the file manager (Files by Google on UMIDIGI phones) and confirm the USB drive shows up under storage devices. 3. Go back to Internal storage, DCIM, Camera, where your camera photos live. 4. Select the photos (long-press the first, tap the rest, or select all). 5. Tap Copy, then select the USB drive, and wait for the copy to finish — don't unplug the drive until the file manager says it's done. Eject the drive from the notification or from Settings > Storage before unplugging it. Use Copy, not Move: Move deletes the originals as it goes, so a bumped cable halfway through loses photos. This works fine for a one-off copy. Its limits are the reason SnapDisk exists: you pick files one by one, there is no progress detail beyond a spinner, no resume if you unplug mid-copy, no verification that every file actually arrived, and you have to repeat the whole manual selection next time photos pile up. For a library that grows every day, the app's oldest-first background copy is the calmer option.

What this does not do

A few honest limits, so the automatic copy is not oversold:

  • Photos and videos only. SnapDisk copies image and video files. Documents, voice notes, and anything that isn't a photo or video is skipped — Google backup is the tool if you want contacts, messages, and settings in the same backup, not just photos.
  • Only the folder you pick. By default that's DCIM — your camera photos. Photos in other folders (Downloads, app folders) only copy if you point the From folder at them, or at a parent folder that contains them.
  • Free 5 GB per run. A library bigger than 5 GB stops at the cap; run it again and it picks up where it stopped. Pro ($9.99, one-time) removes the limit and starts the backup automatically when you plug in a disk.
  • Files over 4 GB on FAT32 are skipped. Very long videos on a FAT32 drive are listed with their reason instead of failing the backup. Reformat the drive to exFAT if you need them.
  • It never deletes. SnapDisk only copies. Freeing space on the phone is copy, check the copy on the drive, then delete the originals yourself — never the other way round.
  • OTG is not confirmed on every Bison model. The spec tables list USB OTG as Yes for the Bison, the Bison Pro, the Bison Plus, the Bison 2 Pro, the Bison X10, the Bison X10G, and the Bison X10 Pro — but the Bison X20's OTG host support is unverified (one source lists OTG Support as No, the others list USB Type-C only, and the reviews mention OTG reverse charging only, which powers another device and is not hosting a drive), and the Bison GT, the Bison GT2 Pro, the Bison GT2 Pro 5G, the Bison X10S, and the Bison X10S NFC have no OTG listing in the sources I found, so confirm the drive mounts in Settings > Storage on those models before relying on it. SnapDisk still needs Android 7.0 or later.
  • The original Bison's connector is disputed. GSMArena and MySmartPrice list the original Bison as USB-C, while mobility.com.ng lists it as microUSB v2.0 — so check your own port before buying an adapter: a USB-C flash drive plugs straight into a USB-C port, while a micro-USB port needs a micro-USB OTG adapter instead.
  • The Bison X10 models' Android versions are unverified. I did not verify the Android version of the Bison X10, the Bison X10G, or the Bison X10 Pro in the sources above, so owners of those models should check Settings > About phone first — SnapDisk needs Android 7.0 or later and cannot install on anything older. Every other Bison model I found runs Android 10, 11, 12, or 13.

What to avoid

  • Buying an adapter you don't need — or the wrong one. A USB-C flash drive plugs straight into the Bison, the Bison Pro, the Bison Plus, the Bison 2 Pro, the Bison X10, the Bison X10G, and the Bison X10 Pro, which all have USB-C — so an adapter is only needed for a regular USB-A drive, and it must be a USB-C OTG adapter, not a micro-USB one. A plain USB-C charging cable is not an OTG adapter: it connects the phone to a computer, which is the opposite direction. And if your original Bison turns out to have the microUSB port that mobility.com.ng lists instead of the USB-C that GSMArena and MySmartPrice list, you need a micro-USB OTG adapter, not a USB-C one — check the port first.
  • Mistaking a cloud backup for a photo copy. Google Drive and Google Photos back your phone up to Google's servers — if you want to plug the drive into a computer and open the pictures, you need a plain copy, that is Method 1 or 2, not a cloud backup.
  • Mistaking a PC tool for a phone-to-USB copy. UMIDIGI's own backup advice is a computer copy with a USB cable and a file browser — but it is a copy to a computer, and the backup lands on the PC. If the phone and the drive are all you have, a phone-to-USB copy is the route, not a desktop copy.
  • Mistaking a spec table or a FAQ page for a phone-to-USB guide. The Bison FAQ page and the Bison spec tables are real UMIDIGI pages — but the FAQ only says to connect the phone to a computer and copy the files with a file browser, and the spec tables only list "USB OTG: Yes". Neither of them describes copying your camera roll straight to a USB drive from the phone.
  • Mistaking "OTG reverse charging" for OTG host support. The Bison X20 reviews mention OTG reverse charging — that is the phone sharing its battery with another device, not the phone reading a flash drive. The host evidence for the X20 is absent: one source lists OTG Support as No and the others list USB Type-C only, so test with a drive.
  • Mistaking a microSD card copy for a USB backup. Copying DCIM to a microSD card is a real local copy — the Bison Pro takes a card up to 256 GB, the Bison 2 Pro takes one up to 512 GB, and the Bison X20 takes one up to 1 TB — but the card stays in the phone, and opening it anywhere else needs a card reader; a USB drive plugs into any computer as it is.
  • PC-only tools when you have no computer. Drag-and-drop through a Windows PC works — but it needs the PC in between. If the phone and the drive are all you have, a phone-to-USB copy is the route — that is the gap this article fills, as of November 18, 2026.
  • Cloud backup dressed as USB backup. If the app needs an account and an upload before your photos are safe, that's a cloud subscription with a USB step. Your photos sit on someone else's server, and the backup stops working the day you stop paying. On UMIDIGI the cloud routes are Google Photos and Google Drive — and Google Photos' "Storage saver" setting compresses photos, which is the one place quality actually gets lost.
  • Installing SnapDisk on a Bison that is too old to run it. The Bison X10, X10G, and X10 Pro have unverified Android versions in my sources — SnapDisk needs Android 7.0 or later. Check Settings > About phone before installing on those models; every other Bison model I found runs Android 10, 11, 12, or 13.
  • Deleting before verifying. A backup is only a backup once you've confirmed the copy. Copy, open a few photos on the drive, then delete from the phone — never the other way round. SnapDisk only copies — it never deletes — so the delete step is always yours, and always after the check.
  • Moving instead of copying. The file manager's Move option copies and then deletes the originals in one step. If the copy fails halfway, photos are already gone from the phone. Copy first, verify, then delete.
  • Unplugging mid-copy. Pulling a USB drive out while files are still writing can corrupt the file in flight. Wait for the copy to finish, or pause it first — SnapDisk's Stop button exists for exactly this.

Rule of thumb: if you have to pick the files yourself, it isn't a backup — it's a chore you will skip. Automate the copy, check it on the drive, then delete from the phone.
