Back up work-profile photos to a USB drive from Android

A personal-profile app cannot see your work photos — Android keeps the two profiles in separate storage. The backup has to start inside the work profile, or the photos have to cross to personal first. Here are the routes that actually work, and the ones that don't.

November 23, 2026 · 6 min read

TL;DR: SnapDisk installed in your personal profile cannot back up work-profile photos — Android gives the work and personal profiles separate storage areas, and a file path valid in one profile is not valid in the other, so your personal apps simply never see the work photos. There are four honest routes, each with its own limit. (1) Copy inside the work profile with the work profile's own file manager — the only route that needs no crossing and no cloud — but whether a USB drive even appears in the work profile's Files app is unverified from Android's documentation, so try it and fall back if it doesn't show up. (2) Share from the work Gallery to a personal app — the share sheet offers personal apps only if your IT policy allows it; sharing work to personal is blocked by default on personally-owned devices, and copy/paste work to personal is blocked on many managed devices. (3) A work-profile cloud account (OneDrive or Google Drive inside the work profile) as a bridge — a fallback, not a USB backup, and the copy dies with the work account if you lose access to it. (4) Installing SnapDisk inside the work profile — the work Play Store is managed and SnapDisk isn't on Google Play at all, and side-loading is usually IT-blocked, so do not plan on this route. The sharpest motive is leaving the job: deleting a work profile deletes all of its local data, so back the photos up and verify the copy before the profile is removed. SnapDisk's one-tap copy works once the photos are in the personal profile — free up to 5 GB per run, Pro $9.99 once — and SnapDisk copies, it never deletes. As of November 23, 2026, no top search result offers a phone-direct USB-drive backup of work-profile photos — the generic OTG guides never mention a work profile, the profile-sharing explainers never take the USB step, and the one guide about backing up before removing a work profile sends the USB copy through a cable to a computer.

SnapDisk cannot see your work photos — say it first

This is the fact the whole article turns on, so here it is with the evidence, not the claim. Android's own developer documentation on work profiles says it plainly: "Since the personal and work profiles have separate storage areas, a file URI that is valid on one profile is not valid on the other." A work profile is a separate, IT-controlled environment on the same phone — the apps in it, and the data in those apps, live apart from your personal apps and data. SnapDisk installed in your personal profile reads your personal profile's MediaStore library — the images and videos tables, oldest-first by date taken, verified in the code — and work-profile photos are not in that library. They are not hidden, or locked, or waiting for a permission: they are in a different storage area that your personal apps cannot reach.

So the first step is not a backup method at all. It is finding out which profile holds the photos. Work-profile apps carry a briefcase badge on their icon. Photos taken with the work camera app, saved inside a work app, or received as attachments in a work email or chat app live in the work profile. Photos taken with your personal camera, and everything in your personal Gallery, live in the personal profile — and those are the ones SnapDisk can already back up. If you are not sure, open both Galleries: the work one (briefcase badge) and the personal one, and see which shows the photos you care about. The rest of this article is about the photos that live in the work one.

One more scope fact before the methods, because it decides which of them SnapDisk can help with at all. SnapDisk copies image and video files only. On the default run it reads the phone's MediaStore images and videos tables, with no folder filter — the whole personal library, oldest-first, whatever folder the photos sit in. On the From-picker route it walks the folder you picked and keeps only recognised photo and video extensions. A backup run that finishes green has copied your personal photos — it has not touched the work profile, and the count it reports is the personal count. If the number looks too small for what you expected, that is probably why: the work photos were never in the run. Keep that in mind through Methods 1 to 4: the question is never "can SnapDisk copy these photos" in the abstract. It is "are these photos in the profile SnapDisk runs in."

What the search results actually offer

Search for this job three ways and the results split into three shapes, none of them the narrow job — a phone-direct backup of work-profile photos onto a USB drive plugged into the phone, no computer, oldest-first, one tap, background with progress, Pause and Stop, resume and verification. The first shape is the generic OTG copy guide: Dr.Fone's "transfer photos from Android to a USB flash drive", Pixoneye, FotoSafe, and our own automatic-transfer article. They all describe the same steps — plug the drive in, open the file manager, copy DCIM by hand — and none of them mentions a work profile at all. They assume every photo on the phone is visible to the file manager doing the copying, which is exactly what is false on a phone with a work profile.

The second shape is the profile-sharing explainer: the Intune MDM manual on data sharing between work and personal profiles, the How-To Geek profiles explainer, the appitika work-profile setup guide, and a Maine IT migration document. These explain the boundary — what can and cannot cross between profiles, and how an admin controls it — but none of them is a photo-backup-to-USB guide. The USB leg is missing everywhere: they stop at "share the file to the other profile" and never take the step onto a drive. The Maine IT document does confirm the sharpest motive, in plain words: removing a work profile deletes all its data, so "ensure that any needed data is backed up before removing the work profile." It just doesn't say how to get that data onto a USB drive.

The third shape is the closest near-miss, and it is worth naming honestly: a guide titled "Back Up Galaxy Photos and Files Before Removing a Work Profile" (umatechnology.org), found on the third phrasing scored for this article. It is Samsung-specific, it is about exactly the right problem — copy and verify anything you need before removing the profile, because Android deletes the profile's local data when it is deleted — and its methods are a USB cable to a computer, Google Photos, another approved cloud service, or standard Android device backup. Its USB method needs a computer. There is no route in it for a drive plugged directly into the phone. So the gap stands, but only on the narrow angle: the phone-direct USB-drive backup of work-profile photos, with the copy, the manual fallback, and the honest statement about what SnapDisk can and cannot do in one guide. That is the angle this article is written on.

What you need

An Android phone with a work profile (look for the briefcase badge on some of your apps); a USB drive your phone can read — a USB-C flash drive, or a regular USB drive with a USB-C OTG adapter (most modern Android phones support OTG; if the phone doesn't see the drive, try a different adapter); and enough space on the drive for the photos you want to keep. One format note: drives formatted FAT32 can't hold a single file over 4 GB. That only matters for very long videos — SnapDisk skips those files and lists them instead of failing the whole backup. A drive formatted exFAT has no such limit.

Before any method, check which profile holds the photos, as above — the work Gallery (briefcase badge) or the personal one. And one warning up front, because it applies to every route below: your IT policy may block any of them. If a step is missing — no USB drive in the work Files app, no Personal tab in the share sheet, no way to install an app in the work profile — that is policy, not a broken phone. Do not try to work around the management controls; ask IT what backup method is approved. The umatechnology guide says the same thing: if USB transfer is blocked or work data cannot be copied, stop and ask the administrator.

Method 1: copy inside the work profile, by hand

This is the route to try first, because it is the only one that needs no crossing between profiles and no cloud account. Everything happens inside the work profile: the photos start there, the copy happens there, and the drive is the destination. Plug the USB drive into the phone. Then open the work profile's Files app — the one with the briefcase badge, not your personal Files app — and look for the USB drive under storage. If it appears, browse to the work photos (in the work Gallery, or Internal storage → DCIM → Camera inside the work profile), select them, tap Copy to, and choose the USB drive as the destination. Wait for the copy to finish before unplugging, and then verify it: plug the drive into another device and open a few photos, and confirm they render.

The honest limit of this route is the one stated in the TL;DR, and it is worth spelling out because it is the difference between a guide and a guess. Whether a USB drive plugged into the phone appears in the work profile's Files app is unverified from Android's documentation: the developer docs confirm the profiles have separate storage areas, but they say nothing about whether a USB volume is visible per profile, and no source found for this article answers it either way. It may appear, and on many phones it will — USB storage is device-wide hardware, not a per-profile folder — but that is an expectation, not a verified fact. So treat this method as a test, not a promise: plug the drive in, open the work Files app, and look. If the drive is there, copy by hand and you are done. If it is not there, the route is closed on your phone — do not keep tapping around hoping it appears — and the fallback is Method 2 or Method 3. One more policy limit: an organisation can block USB file transfer entirely, so if the drive never appears anywhere on the phone, that may be the reason, and IT is the only source for the answer.

If the copy works, remember what it is: a manual copy. There is no oldest-first order, no progress bar with speed and time left, no Pause and Stop, and no resume if you unplug mid-copy. Copy in batches small enough to finish, check the count against what you selected, and open a few files on another device before you trust the drive. And the files on the drive are plain files — anyone who picks up the drive can open them — so if the photos are sensitive, this route protects nothing except against losing the phone.

Method 2: share from the work app to a personal app

If the drive doesn't appear in the work profile, the next route is to move the photos across the boundary into the personal profile, where your personal apps — and SnapDisk — can see them. In the work Gallery or work Photos app, select the photos, tap Share, and look for your personal apps in the share sheet. When cross-profile sharing is allowed, the share sheet offers a Personal tab (or lists personal apps alongside work ones): share to your personal Files app, or to your personal Gallery, and the photos are copied into the personal profile. Once they are personal-profile files, Method 4 below backs them up to the USB drive with one tap.

The honest limit: this route is the one your IT policy most often closes. By default on personally-owned devices, sharing from work to personal is blocked, while sharing from personal to work is allowed — the boundary is deliberately one-way. Microsoft's Intune documentation says the same thing about its "Device default" setting: on Android 6.0 and newer, sharing from the personally-owned work profile to the personal profile is blocked, and an admin has to change the setting to "No restrictions on sharing" to open it. On company-owned devices the admin has broader control and can lock down both directions. So if the share sheet shows no Personal tab and no personal apps, sharing is blocked — that is the policy working as designed, not a missing feature, and there is no setting on your side that opens it. Ask IT whether cross-profile sharing is allowed and, if it is not, what backup method they approve instead. Copy and paste from work to personal is blocked on many managed devices by the same policy family, so don't expect the clipboard to succeed where the share sheet failed.

Two things to know if sharing does work. First, sharing copies the file — the original stays in the work profile until the profile itself is removed, so you now have two copies, and the work one is still at risk. Second, check the shared copies before you rely on them: open a few in the personal Gallery and confirm they are the full photos, not thumbnails, and that videos play. A share that silently downscaled or truncated a file is worse than a share that failed loudly.

Method 3: work-profile cloud as a bridge — not a USB backup

The third route goes through a cloud account that lives inside the work profile — OneDrive or Google Drive signed in with your work account, in the work profile's instance of the app. Upload the photos from the work app to that account, wait for the upload to finish, and then check from another device or a browser that the photos are actually in the account — a pending upload is not a verified copy, and a backup setting alone proves nothing. This gets the photos off the phone, which is the urgent part when a profile removal is coming.

Label this honestly: it is a fallback, not a USB backup. The photos leave the phone to a work account, not to a drive you hold, and getting them back after the profile is removed depends on keeping access to that work account. Your work account data stays reachable from a computer or a browser after the profile is gone — but if the account itself is closed when you leave, the cloud copy closes with it. The umatechnology guide makes the same distinction: a cloud copy is useful only if you can sign in and retrieve it after removal, so keep the credentials available. And do not rely on standard Android device backup as the route: Google says it may be unavailable when a personal device has a work profile, when the device is set up for work only, or when it is company-owned.

If the cloud copy is verified and you can still reach the account, the photos can come back down to the personal profile — download them there, or open them on a computer and copy them to the USB drive directly — and then Method 4 handles the drive copy. But if the only copy of the photos is in a work account you are about to lose, that is not a backup. It is a countdown. The USB drive is the copy that survives the job ending; the cloud is the bridge that gets the photos there.

Method 4: SnapDisk's one-tap copy, once the photos are personal

Method 5: installing SnapDisk inside the work profile

It sounds like the clean fix — put SnapDisk in the work profile, and it would see the work photos the same way it sees personal ones. Do not plan a backup around it. The work Play Store is a managed store: only the apps your IT admin approves appear in it, and an admin can push or block apps at will. SnapDisk is not on Google Play at all yet, so it cannot be installed from the managed Play Store in either profile — there is no listing for IT to approve. The other way in is side-loading the APK inside the work profile, and that needs the install-from-unknown-sources allowance, which an admin can block with the DISALLOW_INSTALL_UNKNOWN_SOURCES restriction — Android's Enterprise security documentation lists blocking apps from unknown sources as a standard profile-owner capability, and on most managed devices it is blocked. So the route needs two things you don't control — a Play listing that doesn't exist yet, and an IT decision to allow it — and neither is yours to make.

If IT does approve and install it one day, then SnapDisk inside the work profile would read the work profile's MediaStore and back up work photos the same way it backs up personal ones today — oldest-first, size-verified, Pause and Stop, 5 GB free per run, Pro $9.99 once. But that is a conditional, not a claim: no one has installed SnapDisk in a work profile, and no test has run there. Until the Play listing exists and IT says yes, Method 5 is a request to make, not a backup to rely on.

Leaving the job? Back up before the profile is removed

This is the sharpest motive for the whole article, and the one with the least room for error. Android Enterprise warns, in the words quoted by both the umatechnology guide and the Maine IT migration document: "After the Work Profile is deleted, all local data on the device within that profile is deleted." Every photo stored in a work-profile app — the work Gallery, the work camera roll, attachments inside work apps — goes with it. The removal itself is one menu away: on a Pixel it is Settings > Passwords, Passkeys & Accounts > Remove work profile > Delete, and on a Samsung the steps vary by model. Your organisation can also remove the profile remotely, without you tapping anything.

So the order matters, and it is not negotiable: back up first, verify the copy on another device second, remove the profile third. Open several photos from the drive on a computer and confirm they render; confirm the count matches what the work Gallery showed. Only then remove the profile. After removal, check that the work profile and its management app are gone as expected — and know what survives: your work account data is still available when you sign in with a computer, a web browser, or another authorised mobile device, but that refers to account data, not to local files deleted with the profile. The local photos do not come back. If you are leaving and the photos matter — site photos, whiteboard shots, the record of a project, pictures that happen to live in the work camera roll — the backup is the job, and the removal is the deadline.

What to avoid

  • Assuming SnapDisk backs up work photos. It cannot see them. A personal-profile app reads the personal profile's MediaStore, and the work photos are in a different storage area. If the photos matter and they live in the work profile, Methods 1 to 3 are the routes — SnapDisk is the last step, not the first.
  • Trusting a green personal backup to have covered the work photos. A backup that copied everything in the personal library copied zero work-profile photos. Check the count against what the work Gallery shows before you call it done.
  • Sharing work photos to personal when policy blocks it. If the Personal tab is missing from the share sheet, sharing is blocked by design. Trying to work around management controls is how people lose access or break policy — ask IT what method is approved instead.
  • Assuming the drive appears in the work Files app. Unverified from Android's documentation. Plug it in, look, and if it isn't there, move to Method 2 or 3 instead of tapping around hoping it appears.
  • Treating a cloud upload as a USB backup. A work-account cloud copy is a bridge, not a backup: it dies with the work account if you lose access to it. The USB drive is the copy that survives the job ending.
  • Deleting the profile before verifying. Profile removal deletes all of its local data. Copy, open a few photos on the drive on another device, then remove the profile — never the other way round. SnapDisk only copies — it never deletes — so the delete step is always yours, and always after the check.
  • Assuming the copy keeps running with the screen off. Unverified — no wake lock, no battery-saver handling in the repo — so keep the phone awake for the run, or check it. Screen-off continuation under battery saver is unverified, and a run that stopped when the screen went dark is the expected failure, not a surprise.
  • Unplugging mid-copy. Pulling a USB drive out while files are still writing can corrupt the file in flight. Wait for the copy to finish, or pause it first — SnapDisk's Stop button exists for exactly this.

Rule of thumb: the profile is the boundary — the backup has to start inside the work profile, or the photos have to cross to personal first. Check which profile holds the photos before you trust any backup, and back them up before the profile is removed, not after.
