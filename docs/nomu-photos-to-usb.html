Method 1: SnapDisk (one tap, background copy)

SnapDisk is a free Android app that does exactly this job and nothing else. Install it from the v0.1.2 APK (it's not on Google Play yet), then:

  1. Plug in the USB drive. It mounts on plug-in on most Android phones with USB host support — look for a "USB storage added" notification. If nothing appears, check Settings > Storage for the drive. The S10 Pro, the S30 Mini, the M6, the M8, and the T18 all list OTG support in the sources I found, so the drive mounting is the test itself: if it appears in Settings > Storage, the phone hosts drives and the rest of this method works; if it never appears, the phone does not host drives and Method 4 is the route. The S10, the S20, and the S30 run Android 6.0, below SnapDisk's Android 7.0 minimum, so SnapDisk cannot run on those three at all.
  2. Open SnapDisk and check the folders. The app opens to a settings screen with a From folder and a To folder, each with a folder picker. The defaults are already right for most people: From /sdcard/DCIM (your camera photos — Nomu camera photos live in DCIM/Camera), To /disk/DCIM on the drive. If your photos live somewhere else, tap the From picker and choose that folder — the picker is the Android system folder picker, and the app keeps access to it.
  3. Tap Backup. SnapDisk offers a backup in a notification when the drive connects: "External storage is connected. Backup photos?" Tap it and your whole library copies oldest-first — your earliest photos first — in the background, while you use the phone normally. The copy mirrors the source folder structure on the drive, so DCIM stays DCIM.
  4. Watch the progress notification — real percent, copied / total size, speed, and time left — with Pause and Stop. You can pause and resume any time.
  5. Wait for "Backup complete." Every file is size-verified after copying, so the counts are proof, not a promise. Files that already copied are never copied twice — so if the free 5 GB per-run limit stops a big library partway, just run it again and it picks up where it left off.

The copies are the original files. SnapDisk streams each file byte-for-byte from the phone to the drive — the code reads the file and writes the same bytes out, with no decode, no recompression, and no resize — and then checks that the copy on the drive is the same size as the original. Other apps copy originals byte-for-byte too; what SnapDisk adds is the automated whole-library run: oldest-first order, progress with Pause and Stop, resume where it stopped, and skip-if-already-copied on the next run. If a file is corrupt or too big for FAT32, it's retried once, then skipped with its reason listed — it never stalls the whole backup. The free version backs up manually, up to 5 GB per backup run, with no ads, no account, and no cloud. SnapDisk Pro is a one-time $9.99 purchase (no subscription) that starts the backup automatically when you plug in a disk and removes the size limit. The app has no internet permission, so your photos physically cannot leave your device.

Method 2: a file manager (the stock route, no app needed)

A file manager can copy your photos to the USB drive — the YouTube guides' route is an OTG connection with the built-in file manager, and askfilo's route is the same, and either is the manual route for external storage: 1. Plug in the USB drive — a notification should appear saying "USB storage added"; tap it to open the drive. If nothing appears, check Settings > Storage for the drive. 2. Open the file manager (Files by Google on Nomu phones) and confirm the USB drive shows up under storage devices. 3. Go back to Internal storage, DCIM, Camera, where your camera photos live. 4. Select the photos (long-press the first, tap the rest, or select all). 5. Tap Copy, then select the USB drive, and wait for the copy to finish — don't unplug the drive until the file manager says it's done. Eject the drive from the notification or from Settings > Storage before unplugging it. Use Copy, not Move: Move deletes the originals as it goes, so a bumped cable halfway through loses photos. This works fine for a one-off copy. Its limits are the reason SnapDisk exists: you pick files one by one, there is no progress detail beyond a spinner, no resume if you unplug mid-copy, no verification that every file actually arrived, and you have to repeat the whole manual selection next time photos pile up. For a library that grows every day, the app's oldest-first background copy is the calmer option.

Google Photos is Google's own photo backup app, and it is the stock photo backup on Nomu Android phones: it automatically backs up photos to your Google account. It is a real backup — but it is a cloud backup, not a USB copy, and photos sync through Google Photos instead. 2. None of them is a one-tap way to copy your camera roll to a drive. All of them work fine for what they are. Their limit, for photos specifically: none of them gives you a folder of plain photo files on a USB drive you can plug into any computer and open. If what you want is a copy of your photos you can open anywhere, Method 1 or 2 is the route — that is the gap this article fills, as of November 18, 2026.

If a PC or Mac is handy, the old route still works — and it is the route Nomu's own backup advice names: plug the Nomu phone into the computer with a USB cable, tap the USB notification and choose File transfer — and drag the DCIM folder onto the USB drive. What this does not do

A few honest limits, so the automatic copy is not oversold:

  • Photos and videos only. SnapDisk copies image and video files. Documents, voice notes, and anything that isn't a photo or video is skipped — Google backup is the tool if you want contacts, messages, and settings in the same backup, not just photos.
  • Only the folder you pick. By default that's DCIM — your camera photos. Photos in other folders (Downloads, app folders) only copy if you point the From folder at them, or at a parent folder that contains them.
  • Free 5 GB per run. A library bigger than 5 GB stops at the cap; run it again and it picks up where it stopped. Pro ($9.99, one-time) removes the limit and starts the backup automatically when you plug in a disk.
  • Files over 4 GB on FAT32 are skipped. Very long videos on a FAT32 drive are listed with their reason instead of failing the backup. Reformat the drive to exFAT if you need them.
  • It never deletes. SnapDisk only copies. Freeing space on the phone is copy, check the copy on the drive, then delete the originals yourself — never the other way round.
  • Three Nomu models cannot run SnapDisk at all. The S10, the S20, and the S30 run Android 6.0, below SnapDisk's Android 7.0 minimum — so SnapDisk cannot install on any of the three, even though the S20 and the S30 list OTG support. Their photos move off the phone by file manager or computer copy instead.
  • The S10's OTG support is unconfirmed. PhoneMore lists the S10 as microUSB 2.0 with no OTG mention, and no OTG in its feature list — so confirm the drive mounts in Settings > Storage before relying on it. SnapDisk still needs Android 7.0 or later, which the S10 does not have.
  • The specs are disputed on several models. The S20 chipset is MediaTek MT6735 per Review Hub against MT6737T per UL benchmarks; the T18 chipset is MT6737 per gizmochina against MT6737T per unite4buy; the M8 Android version is 7.0 per phonesdata and devicesfaq against 7.1 per unite4buy, and its battery is 2950 mAh per devicesfaq against 3000 mAh per unite4buy; the microSD size is disputed on the S10 Pro (up to 64 GB per PhoneMore, up to 32 GB per Smartprix), the S30 (up to 64 GB per PhoneMore, up to 32 GB per Notebookcheck), and the M6 (up to 32 GB per Notebookcheck, up to 64 GB per unite4buy) — so check Settings > About phone on those models before trusting either spec set. Either way the S10 Pro, the S30 Mini, the M6, the M8, and the T18 run Android 7.0, so SnapDisk installs if the phone mounts a drive.
  • The M8 is the only Nomu model with USB-C. phonesdata lists the M8 as USB Type-C with OTG, and devicesfaq lists USB Type-C with no OTG mention — so a USB-C flash drive plugs straight into the M8, while the S10 Pro, the S30 Mini, the M6, and the T18 have microUSB 2.0 and need a micro-USB OTG adapter. Check your own port before buying an adapter.

What to avoid

  • Buying an adapter you don't need — or the wrong one. A micro-USB OTG adapter is what the S10 Pro, the S30 Mini, the M6, and the T18 need for a regular USB-A drive, since all four have microUSB 2.0 — so a USB-C OTG adapter is the wrong one for them. The M8 has USB-C instead, so it needs a USB-C OTG adapter for a regular USB-A drive, or a USB-C flash drive plugs straight in. A plain micro-USB charging cable is not an OTG adapter: it connects the phone to a computer, which is the opposite direction.
  • Mistaking a cloud backup for a photo copy. Google Drive and Google Photos back your phone up to Google's servers — if you want to plug the drive into a computer and open the pictures, you need a plain copy, that is Method 1 or 2, not a cloud backup.
  • Mistaking a PC tool for a phone-to-USB copy. Nomu's own backup advice is a computer copy with a USB cable and a file browser — but it is a copy to a computer, and the backup lands on the PC. If the phone and the drive are all you have, a phone-to-USB copy is the route, not a desktop copy.
  • Mistaking a spec table or a FAQ page for a phone-to-USB guide. The S10 FAQ page and the Nomu spec tables are real Nomu pages — but the FAQ only says to connect the phone to a computer and copy the files with a file browser, and the spec tables only list "USB OTG" or a USB connector type. Neither of them describes copying your camera roll straight to a USB drive from the phone.
  • Mistaking OTG support for SnapDisk support. The S20 and the S30 both list OTG support — Review Hub lists "USB OTG: YES" for the S20, and PhoneMore and Notebookcheck list OTG for the S30 — but both run Android 6.0, below SnapDisk's Android 7.0 minimum. OTG lets a file manager copy photos to a drive; it does not make the phone new enough to install SnapDisk. Test with a drive, and use Method 2 or 4 on those models.
  • Mistaking a microSD card copy for a USB backup. Copying DCIM to a microSD card is a real local copy — the S10 takes a card up to 64 GB, the S30 Mini takes one up to 64 GB, and the T18 takes one up to 32 GB — but the card stays in the phone, and opening it anywhere else needs a card reader; a USB drive plugs into any computer as it is.
  • PC-only tools when you have no computer. Drag-and-drop through a Windows PC works — but it needs the PC in between. If the phone and the drive are all you have, a phone-to-USB copy is the route — that is the gap this article fills, as of November 18, 2026.
  • Cloud backup dressed as USB backup. If the app needs an account and an upload before your photos are safe, that's a cloud subscription with a USB step. Your photos sit on someone else's server, and the backup stops working the day you stop paying. On Nomu the cloud routes are Google Photos and Google Drive — and Google Photos' "Storage saver" setting compresses photos, which is the one place quality actually gets lost.
  • Installing SnapDisk on a Nomu phone that cannot run it. The S10, the S20, and the S30 run Android 6.0 — SnapDisk needs Android 7.0 or later and cannot install on any of the three. Check Settings > About phone before installing; every other Nomu model I found runs Android 7.0.
  • Deleting before verifying. A backup is only a backup once you've confirmed the copy. Copy, open a few photos on the drive, then delete from the phone — never the other way round. SnapDisk only copies — it never deletes — so the delete step is always yours, and always after the check.
  • Moving instead of copying. The file manager's Move option copies and then deletes the originals in one step. If the copy fails halfway, photos are already gone from the phone. Copy first, verify, then delete.
  • Unplugging mid-copy. Pulling a USB drive out while files are still writing can corrupt the file in flight. Wait for the copy to finish, or pause it first — SnapDisk's Stop button exists for exactly this.

Rule of thumb: if you have to pick the files yourself, it isn't a backup — it's a chore you will skip. Automate the copy, check it on the drive, then delete from the phone.
