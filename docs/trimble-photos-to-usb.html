What you need

Method 1: SnapDisk (one tap, background copy)

SnapDisk is a free Android app that does exactly this job and nothing else. Install it from the v0.1.2 APK (it's not on Google Play yet), then:

  1. Check your model can run SnapDisk. The TDC600 runs Android 8.0 at launch (Android 10 in Trimble's later docs) and the TDC650 runs Android 10 — both clear the Android 7.0 minimum, so SnapDisk installs on both. The TSC7 and the T7 run Windows 10, the TSC3 runs Windows Mobile, and the Juno T41 and the Geo 7X run Windows Embedded Handheld, so none of those can run SnapDisk, and Method 4 is the route on them. The TCU5 runs Android 7.1.1 and clears the minimum, but it has no camera at all, so there are no photos to back up on it. If you are unsure which version your unit runs, check Settings > About phone. Both covered models have the Play Store — they are Google Mobile Services certified — so no sideload is needed; today install the APK from the GitHub release page, and from Play once the listing is live.
  2. Plug in the USB drive — and check it mounts. Both models have only a USB-C port, so connect the drive with a USB-C OTG adapter. A USB-C dual drive plugs straight in with no adapter. It mounts on plug-in on most Android devices with USB host support — look for a "USB storage added" notification. If nothing appears, check Settings > Storage for the drive, or run a USB OTG Checker app from the Play Store. No source found labels either model's port OTG — both datasheets say only USB 3.0 (Type-C) — so this mount check is the step that confirms the backup can work at all; if the drive never mounts, Method 4 is the route.
  3. Open SnapDisk and check the folders. The app opens to a settings screen with a From folder and a To folder, each with a folder picker. The defaults are already right for most people: From /sdcard/DCIM (your camera photos — Trimble camera photos live in DCIM/Camera), To /disk/DCIM on the drive. If your photos live somewhere else, tap the From picker and choose that folder — the picker is the Android system folder picker, and the app keeps access to it.
  4. Tap Backup. SnapDisk offers a backup in a notification when the drive connects: "External storage is connected. Backup photos?" Tap it and your whole library copies oldest-first — your earliest photos first — in the background, while you use the device normally. The copy mirrors the source folder structure on the drive, so DCIM stays DCIM.
  5. Watch the progress notification — real percent, copied / total size, speed, and time left — with Pause and Stop. You can pause and resume any time.
  6. Wait for "Backup complete." Every file is size-verified after copying, so the counts are proof, not a promise. Files that already copied are never copied twice — so if the free 5 GB per-run limit stops a big library partway, just run it again and it picks up where it left off.

The copies are the original files. SnapDisk streams each file byte-for-byte from the device to the drive — the code reads the file and writes the same bytes out, with no decode, no recompression, and no resize — and then checks that the copy on the drive is the same size as the original. Other apps copy originals byte-for-byte too; what SnapDisk adds is the automated whole-library run: oldest-first order, progress with Pause and Stop, resume where it stopped, and skip-if-already-copied on the next run. If a file is corrupt or too big for FAT32, it's retried once, then skipped with its reason listed — it never stalls the whole backup. The free version backs up manually, up to 5 GB per backup run, with no ads, no account, and no cloud. SnapDisk Pro is a one-time $9.99 purchase (no subscription) that starts the backup automatically when you plug in a disk and removes the size limit. The app has no internet permission, so your photos physically cannot leave your device.

Method 2: a file manager (the stock route, no app needed)

A file manager can copy your photos to the USB drive — the generic guides' route is an OTG connection with the built-in file manager, and it is the manual route for external storage: 1. Plug in the USB drive with a USB-C OTG adapter and check it mounts — look for a "USB storage added" notification; if nothing appears, check Settings > Storage for the drive. No source found labels either model's port OTG, so this check comes first. 2. Open the file manager and confirm the USB drive shows up under storage devices. 3. Go back to Internal storage, DCIM, Camera, where your camera photos live. 4. Select the photos (long-press the first, tap the rest, or select all). 5. Tap Copy, then select the USB drive, and wait for the copy to finish — don't unplug the drive until the file manager says it's done. Eject the drive from the notification or from Settings > Storage before unplugging it. Use Copy, not Move: Move deletes the originals as it goes, so a bumped cable halfway through loses photos. This works fine for a one-off copy. Its limits are the reason SnapDisk exists: you pick files one by one, there is no progress detail beyond a spinner, no resume if you unplug mid-copy, no verification that every file actually arrived, and you have to repeat the whole manual selection next time photos pile up. For a library that grows every day, the app's oldest-first background copy is the calmer option. Two notes: Trimble Access has its own USB copy — the TSC5 support note describes copying job files to a USB drive from inside Trimble Access — but that copies survey jobs, not your camera roll, so it is not Method 2 for photos; and no source found names the stock file manager on a Trimble handheld — the steps above use the built-in file manager, whatever it is called on your unit, and Trimble Mobile Manager is not a file manager.

What this does not do

A few honest limits, so the automatic copy is not oversold:

  • Photos and videos only. SnapDisk copies image and video files. Documents, voice notes, and anything that isn't a photo or video is skipped — Google backup is the tool if you want contacts, messages, and settings in the same backup, not just photos.
  • Only the folder you pick. By default that's DCIM — your camera photos. Photos in other folders (Downloads, app folders) only copy if you point the From folder at them, or at a parent folder that contains them.
  • Free 5 GB per run. A library bigger than 5 GB stops at the cap; run it again and it picks up where it stopped. Pro ($9.99, one-time) removes the limit and starts the backup automatically when you plug in a disk.
  • Files over 4 GB on FAT32 are skipped. Very long videos on a FAT32 drive are listed with their reason instead of failing the backup. Reformat the drive to exFAT if you need them.
  • It never deletes. SnapDisk only copies. Freeing space on the device is copy, check the copy on the drive, then delete the originals yourself — never the other way round.
  • OTG is not labelled on either model. Both datasheets say only USB 3.0 (Type-C) — neither calls the port OTG — so check the drive mounts (look for the mount notification, or run a USB OTG Checker app) before buying an adapter or trusting the setup. If the drive never mounts, the port may not host drives, and the computer copy in Method 4 is the route.
  • One Android version differs by source. The TDC600 is Android 8.0 in Trimble's 2019 datasheet and in the reseller listing, and Android 10 in Trimble's 2021 FAQ and 2023 datasheet — both readings clear the minimum either way, so the version dispute changes nothing about the backup, except that a TDC600 still on Android 8.0 cannot run FotoSafe, which needs Android 9. Check Settings > About phone if you are unsure which version your unit runs.
  • The TDC650's Android security updates ran until December 2024. Its datasheet footnote says so — the device still runs, but check Settings for updates, and do not assume it is on the latest patches.
  • No source found names the stock file manager on a Trimble handheld. Method 2 uses the built-in file manager, whatever it is called on your unit — and Trimble Mobile Manager, pre-installed on the TDC650, manages the device; it is not a file manager.
  • No source found states the port position in text on either model. The TDC650 user guide numbers the USB-C/charging port as part 18 in its diagram, but no source found states the position in text, so check your unit before buying a drive or a cable that assumes a port position.
  • Several Trimble models cannot run SnapDisk at all. The TSC7 and the T7 run Windows 10, the TSC3 runs Windows Mobile, and the Juno T41 and the Geo 7X run Windows Embedded Handheld — so SnapDisk cannot install on any of them, and the computer copy in Method 4 is the route. The TCU5 runs Android 7.1.1 and clears the minimum, but it has no camera at all, so there are no photos to back up on it, and it transfers via a docking station.
  • Four more Android Trimble controllers turned up but are not covered. The TSC5 runs Android 10, and the TDC6, the TSC710 and the TSC510 run Android 14 — all four clear the minimum — but no source found labels their USB ports OTG either (the TSC5 datasheet describes its USB-C as for charging and USB 2.0 data transfer to a computer), so the same mount test applies. What to avoid

  • Buying a USB-C OTG adapter before checking the port hosts a drive. Neither datasheet labels the port OTG — both say only USB 3.0 (Type-C) — so plug a drive in first and look for the mount notification, or run a USB OTG Checker app. An adapter is useless if the port never mounts a drive.
  • Assuming Trimble Access's USB copy backs up photos. Trimble Access copies survey job files to a USB drive — the TSC5 support note walks through exactly that — but your camera roll is not a job file, and Trimble Access does not touch it.
  • Assuming the R10 receiver's USB stick download is a phone backup. The receiver downloads logged GNSS data to a stick with a field data cable — it is a receiver, not a handheld, and the files are logged data, not photos.
  • Assuming the TSC3's USB transfer works without a PC. The TSC3 moves files to a USB thumb drive from inside Trimble Access — but its cable route needs Windows Mobile Device Center on a PC, and the TSC3 runs Windows Mobile, so it cannot run SnapDisk at all.
  • Assuming every Trimble handheld runs Android. The TSC7 and the T7 run Windows 10, the TSC3 runs Windows Mobile, and the Juno T41 and the Geo 7X run Windows Embedded Handheld — check Settings > About phone before buying an adapter or installing the app: the Windows models need the computer copy in Method 4.
  • Assuming the TDC600 is on one Android version. The TDC600 is Android 8.0 in Trimble's 2019 datasheet and Android 10 in its 2021 FAQ and 2023 datasheet — check Settings > About phone on your unit instead of trusting a version printed for another source. It matters for rival apps: FotoSafe needs Android 9, so it cannot run on a TDC600 still on Android 8.0.
  • Mistaking Trimble Connect cloud for a photo copy. Trimble Connect is the cloud Trimble lists alongside its controllers — if you want to plug the drive into a computer and open the pictures, you need a plain copy, that is Method 1 or 2, not a cloud service. And Google Photos' "Storage saver" setting compresses photos, which is the one place quality actually gets lost.
  • Mistaking Trimble Mobile Manager for a backup tool. It is pre-installed on the TDC650 — but it manages the device, it does not copy photos anywhere. Managing is not backing up.
  • Mistaking a microSD card copy for a USB backup. Copying DCIM to a microSD card is a real local copy — the TDC600 takes a microSDHC card up to 256 GB and the TDC650 takes a microSDXC card up to 256 GB — but the card stays in the device, and opening it anywhere else needs a card reader; a USB drive plugs into any computer as it is.
  • Mistaking a spec sheet or a product page for a phone-to-USB guide. The Trimble datasheets are real Trimble documents — but they only list an Android version, a processor, a camera, or a USB port type. None of them describes copying your camera roll straight to a USB drive from the device — and none of them even labels the port OTG.
  • Mistaking a drive-locked app for a general backup. Photo Backup Stick DC is a real one-tap backup app — but it only works with genuine Photo Backup Stick OTG drives. If the drive you already own is any other brand, that app cannot use it: SnapDisk, Photos to USB, and FotoSafe work with any drive.
  • PC-only tools when you have no computer. Drag-and-drop through a Windows PC works — but it needs the PC in between. If the device and the drive are all you have, a phone-to-USB copy is the route — that is the gap this article fills, as of November 19, 2026.
  • Cloud backup dressed as USB backup. If the app needs an account and an upload before your photos are safe, that's a cloud subscription with a USB step. Your photos sit on someone else's server, and the backup stops working the day you stop paying. On a Trimble handheld the cloud routes are Google Photos and Google Drive — and Google Photos' "Storage saver" setting compresses photos, which is the one place quality actually gets lost.
  • Deleting before verifying. A backup is only a backup once you've confirmed the copy. Copy, open a few photos on the drive, then delete from the device — never the other way round. SnapDisk only copies — it never deletes — so the delete step is always yours, and always after the check.
  • Moving instead of copying. The file manager's Move option copies and then deletes the originals in one step. If the copy fails halfway, photos are already gone from the device. Copy first, verify, then delete.
  • Unplugging mid-copy. Pulling a USB drive out while files are still writing can corrupt the file in flight. Wait for the copy to finish, or pause it first — SnapDisk's Stop button exists for exactly this.

Rule of thumb: if you have to pick the files yourself, it isn't a backup — it's a chore you will skip. Automate the copy, check it on the drive, then delete from the phone.
