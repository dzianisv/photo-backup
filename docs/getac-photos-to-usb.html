Method 1: SnapDisk (one tap, background copy)

SnapDisk is a free Android app that does exactly this job and nothing else. Install it from the v0.1.2 APK (it's not on Google Play yet), then:

  1. Check your model can host a drive. The ZX70 (Android 6.0) cannot run SnapDisk at all, so Method 4 is the route on that model. Every model except the ZX70 clears the Android 7.0 minimum, so SnapDisk installs on all of them — the question is only whether the drive mounts.
  2. Plug in the USB drive. On the ZX10, a regular USB-A flash drive plugs straight into the dedicated USB 2.0 host port — no adapter needed — while a USB-C drive plugs into the USB-C port. On the ZX80, a USB-C flash drive plugs straight into its USB-C port, and a regular USB-A drive needs a USB-C OTG adapter. It mounts on plug-in on most Android devices with USB host support — look for a "USB storage added" notification. If nothing appears, check Settings > Storage for the drive.   3. Open SnapDisk and check the folders. The app opens to a settings screen with a From folder and a To folder, each with a folder picker.   5. Watch the progress notification — real percent, copied / total size, speed, and time left — with Pause and Stop. You can pause and resume any time.
  6. Wait for "Backup complete." Every file is size-verified after copying, so the counts are proof, not a promise. Files that already copied are never copied twice — so if the free 5 GB per-run limit stops a big library partway, just run it again and it picks up where it left off.

The copies are the original files. SnapDisk streams each file byte-for-byte from the device to the drive — the code reads the file and writes the same bytes out, with no decode, no recompression, and no resize — and then checks that the copy on the drive is the same size as the original. Other apps copy originals byte-for-byte too; what SnapDisk adds is the automated whole-library run: oldest-first order, progress with Pause and Stop, resume where it stopped, and skip-if-already-copied on the next run. If a file is corrupt or too big for FAT32, it's retried once, then skipped with its reason listed — it never stalls the whole backup. The free version backs up manually, up to 5 GB per backup run, with no ads, no account, and no cloud. SnapDisk Pro is a one-time $9.99 purchase (no subscription) that starts the backup automatically when you plug in a disk and removes the size limit. The app has no internet permission, so your photos physically cannot leave your device.

Method 2: a file manager (the stock route, no app needed)

A file manager can copy your photos to the USB drive — the generic guides' route is an OTG connection with the built-in file manager, and it is the manual route for external storage: 1. Plug in the USB drive — on the ZX10, a regular USB-A drive plugs straight into the dedicated host port; on the ZX80, a USB-C drive plugs into the USB-C port, and a USB-A drive needs a USB-C OTG adapter. A notification should appear saying "USB storage added"; tap it to open the drive. If nothing appears, check Settings > Storage for the drive. On the ZX80, the drive mounting is the test itself, since no source I found confirms host or OTG support on that model. 2. Open the file manager (Files by Google on Getac tablets) and confirm the USB drive shows up under storage devices. 3. Go back to Internal storage, DCIM, Camera, where your camera photos live. 4. Select the photos (long-press the first, tap the rest, or select all). 5. Tap Copy, then select the USB drive, and wait for the copy to finish — don't unplug the drive until the file manager says it's done. Eject the drive from the notification or from Settings > Storage before unplugging it. Use Copy, not Move: Move deletes the originals as it goes, so a bumped cable halfway through loses photos. This works fine for a one-off copy. Its limits are the reason SnapDisk exists: you pick files one by one, there is no progress detail beyond a spinner, no resume if you unplug mid-copy, no verification that every file actually arrived, and you have to repeat the whole manual selection next time photos pile up. For a library that grows every day, the app's oldest-first background copy is the calmer option. One note: the file-manager route works on the ZX80 too, if the device hosts the drive at all — it needs no app install, so the Android 7.0 minimum does not apply to it — but that model's host support is just as unconfirmed, so the drive mounting is the test there too.

What this does not do

A few honest limits, so the automatic copy is not oversold:

  • Photos and videos only. SnapDisk copies image and video files. Documents, voice notes, and anything that isn't a photo or video is skipped — Google backup is the tool if you want contacts, messages, and settings in the same backup, not just photos.
  • Only the folder you pick. By default that's DCIM — your camera photos. Photos in other folders (Downloads, app folders) only copy if you point the From folder at them, or at a parent folder that contains them.
  • Free 5 GB per run. A library bigger than 5 GB stops at the cap; run it again and it picks up where it stopped. Pro ($9.99, one-time) removes the limit and starts the backup automatically when you plug in a disk.
  • Files over 4 GB on FAT32 are skipped. Very long videos on a FAT32 drive are listed with their reason instead of failing the backup. Reformat the drive to exFAT if you need them.
  • It never deletes. SnapDisk only copies. Freeing space on the device is copy, check the copy on the drive, then delete the originals yourself — never the other way round.
  • USB host support is confirmed only on the ZX10 line. The ZX10 and the ZX10-Ex G2 spec listings give a dedicated "USB 2.0 (Host)" port — but the ZX80's I/O list is a single USB-C port with no host or OTG mention at all, so plug a drive in and check Settings > Storage on that model before relying on it. The drive mounting is the test.
  • The ZX70 cannot run SnapDisk at all. The ZX70 runs Android 6.0, below SnapDisk's Android 7.0 minimum — so on that model the computer copy in Method 4 is the route, not this article's one-tap method. The ZX80 runs Android 13 (Getac's current spec lists Android 15) and the ZX10 runs Android 11, and the ZX10-Ex G2 runs Android 15 (some older listings say Android 13) — so every ZX model except the ZX70 clears the minimum, and SnapDisk installs on all of them. The blocker on this line is host support, not the Android version.
  • The ZX80's Android version differs by source. Getac's current spec (generated November 10, 2026) lists Android 15, while older datasheets and retailer listings list Android 13 — either way it clears SnapDisk's Android 7.0 minimum by a wide margin, so the version is not the question on this model; whether the drive mounts is.
  • No ZX50 or ZX90 model turned up in the sources found. This article covers only the ZX70, the ZX80 (including the ZX80-Ex), and the ZX10 (including the ZX10 G2 and ZX10-Ex G2) — if your tablet is a different ZX model, check Settings > About phone for its Android version and Settings > Storage for drive mounting, the same two tests used here.
  • The ZX80's host support is unconfirmed. No source I found mentions host or OTG support on the ZX80 (Android 13, or Android 15 in Getac's current spec) — so plug a drive in and check Settings > Storage on that model before relying on it. The drive mounting is the test.
  • Anything below Android 7.0 cannot run SnapDisk at all. The ZX70 runs Android 6.0, so it cannot install SnapDisk — and older Getac tablets exist, so check Settings > About phone if you are unsure: below Android 7.0, SnapDisk cannot install, and the computer copy in Method 4 is the route.

The ZX10 has a dedicated USB 2.0 host port, so a regular USB-A flash drive plugs straight into it with no adapter at all, and a USB-C drive plugs into its USB-C port. The ZX80 has only a USB-C port, so a USB-C flash drive plugs straight into it and a regular USB-A drive needs a USB-C OTG adapter. A plain USB-C charging cable is not an OTG adapter: it connects the device to a computer, which is the opposite direction.

What to avoid

  • Buying an adapter you don't need — or the wrong one. A regular USB-A flash drive plugs straight into the ZX10's dedicated host port — so no adapter is needed on that model at all — while on the ZX80 an adapter is only needed for a regular USB-A drive, and it must be a USB-C OTG adapter. A plain USB-C charging cable is not an OTG adapter: it connects the device to a computer, which is the opposite direction.
  • Assuming host support on the ZX80. The ZX10 lists a dedicated "USB 2.0 (Host)" port — but no source I found mentions host or OTG support on the ZX80. Test with a drive on that model, and use Method 2 or 4 on it if the drive never mounts.
  • Mistaking a cloud backup for a photo copy. Google Drive and Google Photos back your device up to Google's servers — if you want to plug the drive into a computer and open the pictures, you need a plain copy, that is Method 1 or 2, not a cloud backup.
  • Mistaking a PC tool for a phone-to-USB copy. A computer copy with a USB cable moves files to a computer — but it is a copy to a computer, and the backup lands on the PC. If the device and the drive are all you have, a phone-to-USB copy is the route, not a desktop copy.
  • Mistaking a spec table or a product page for a phone-to-USB guide. The Getac datasheets and the ZX10 spec pages are real Getac pages — but the datasheets only list an Android version, a chipset, or a USB connector type, and the spec pages only describe the hardware. Neither of them describes copying your camera roll straight to a USB drive from the device.
  • Mistaking host support on one model for host support on the other. The ZX10 lists a dedicated "USB 2.0 (Host)" port — but no source I found mentions host or OTG support on the ZX80. Test with a drive on that model, and use Method 2 or 4 on it if the drive never mounts.
  • Mistaking a drive-locked app for a general backup. Photo Backup Stick DC is a real one-tap backup app — but it only works with genuine Photo Backup Stick OTG drives. If the drive you already own is any other brand, that app cannot use it: SnapDisk, Photos to USB, and FotoSafe work with any drive.
  • Mistaking a camera-card bridge for a tablet backup. Using a phone as a bridge between a camera's memory card and an SSD is a real field backup — but it backs up the camera's card, not the tablet's own gallery. If your photos are on the ZX10 itself, the drive plugs straight into the tablet, and Method 1 or 2 is the route.
  • Mistaking a microSD card copy for a USB backup. Copying DCIM to a microSD card is a real local copy — the ZX10 and the ZX80 both take a card — but the card stays in the device, and opening it anywhere else needs a card reader; a USB drive plugs into any computer as it is.
  • PC-only tools when you have no computer. Drag-and-drop through a Windows PC works — but it needs the PC in between. If the device and the drive are all you have, a phone-to-USB copy is the route — that is the gap this article fills, as of November 18, 2026.
  • Cloud backup dressed as USB backup. If the app needs an account and an upload before your photos are safe, that's a cloud subscription with a USB step. Your photos sit on someone else's server, and the backup stops working the day you stop paying. On a Getac tablet the cloud routes are Google Photos and Google Drive — and Google Photos' "Storage saver" setting compresses photos, which is the one place quality actually gets lost.
  • Deleting before verifying. A backup is only a backup once you've confirmed the copy. Copy, open a few photos on the drive, then delete from the device — never the other way round. SnapDisk only copies — it never deletes — so the delete step is always yours, and always after the check.
  • Moving instead of copying. The file manager's Move option copies and then deletes the originals in one step. If the copy fails halfway, photos are already gone from the device. Copy first, verify, then delete.
  • Unplugging mid-copy. Pulling a USB drive out while files are still writing can corrupt the file in flight. Wait for the copy to finish, or pause it first — SnapDisk's Stop button exists for exactly this.

Rule of thumb: if you have to pick the files yourself, it isn't a backup — it's a chore you will skip. Automate the copy, check it on the drive, then delete from the device.
