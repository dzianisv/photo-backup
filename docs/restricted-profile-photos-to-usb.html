Back up restricted-profile photos to a USB drive

An owner-profile app cannot see your restricted-profile photos — Android gives the restricted profile its own separate storage, and it wipes that storage when the profile is deleted. The backup has to start inside the restricted profile, or the photos have to cross to the owner profile first. Here are the routes that actually work, and the ones that don't.

November 23, 2026 · 6 min read

TL;DR: SnapDisk installed in your owner profile cannot back up restricted-profile photos — the restricted profile is a separate Android user profile with its own storage area, and a file path valid in one profile is not valid in the other, so your owner-profile apps simply never see the restricted-profile photos. There are four honest routes, each with its own limit. (1) Copy inside the restricted profile with the restricted profile's own file manager — the only route that needs no crossing and no cloud — but whether a USB drive even appears in the restricted profile's Files app is unverified from Android's documentation, so try it and fall back if it doesn't show up. (2) Move the photos to the owner profile before the restricted profile is deleted — upload them to a cloud account signed in inside the restricted profile, or send them to yourself from inside the restricted profile — because the restricted-profile guides give no backup advice at all, and name no owner-visible shared folder on stock Android. (3) A restricted-profile cloud account as a bridge — a fallback, not a USB backup, and the copy dies with that account if you lose access to it. (4) Installing SnapDisk inside the restricted profile — SnapDisk isn't on Google Play at all, the owner decides which apps the profile can see, and side-loading inside a restricted profile is untested, so do not plan on this route. The sharpest motive is the deletion itself: removing the profile erases all of its local data with no restore, so back the photos up and verify the copy before the profile is removed. SnapDisk's one-tap copy works once the photos are in the owner profile — free up to 5 GB per run, Pro $9.99 once — and SnapDisk copies, it never deletes. As of November 23, 2026, no top search result offers a tablet-direct USB-drive backup of restricted-profile photos — the generic OTG guides never mention a restricted profile, and the restricted-profile explainers never take the USB step.

SnapDisk cannot see your restricted-profile photos — say it first

This is the fact the whole article turns on, so here it is with the evidence, not the claim. Android's restricted profile is a profile type in the multi-user system: it "uses accounts based off the parent user, who can control what apps are available on the restricted profile", in the words of Android's own multi-user documentation — and it is available only on tablets and television devices. The owner creates it and picks which apps it can see; every other app is hidden from the profile and cannot be launched there. Underneath, the separation is the same one that keeps every Android user apart: physical internal storage is partitioned into per-user directories, each user runs under a distinct Linux UID range, and one user's apps cannot inspect another user's files. The restricted-profile guides say the same thing in plainer words — the profile only shows the apps and content the owner explicitly allows, and a restricted profile has no Google account of its own unless one is set up inside it.

So the first step is not a backup method at all. It is finding out which profile holds the photos. Photos taken while the tablet was in the restricted profile — with the profile's camera app, or saved inside a profile app, or received as attachments in a profile email or chat app — live in the restricted profile. Photos taken with your owner camera, and everything in your owner Gallery, live in the owner profile — and those are the ones SnapDisk can already back up. If you are not sure, switch into the restricted profile and look: swipe down twice for Quick Settings, tap the user icon, tap the restricted profile, and open its Gallery. If the photos are there, the rest of this article is about them.

One scope distinction before the methods, because it decides which device this article even applies to. A restricted profile is a tablet feature. Android's documentation says it is available only on tablets and television devices, and the setup guides agree: restricted profiles are officially supported on Android 5.0+ tablets, and many phones hide the option entirely — if you don't see "Restricted profile" under Add user or profile, your device does not support it, and the guest account is the fallback the guides point to. If you are on a phone, this article does not apply to you; the routes for a phone's guest profile are in our guest-profile guide. A second distinction: a restricted profile is permanent until the owner deletes it, unlike a guest session, which is wiped when it ends. That makes the backup less urgent day to day — the photos are not on a countdown — but no safer in the end: deleting the profile still erases everything in it.

One more scope fact, because it decides which of them SnapDisk can help with at all. SnapDisk copies image and video files only. On the default run it reads the tablet's MediaStore images and videos tables, with no folder filter — the whole owner library, oldest-first, whatever folder the photos sit in. On the From-picker route it walks the folder you picked and keeps only recognised photo and video extensions. A backup run that finishes green has copied your owner photos — it has not touched the restricted profile, and the count it reports is the owner count. If the number looks too small for what you expected, that is probably why: the restricted-profile photos were never in the run. Keep that in mind through Methods 1 to 4: the question is never "can SnapDisk copy these photos" in the abstract. It is "are these photos in the profile SnapDisk runs in."

What you need

An Android tablet with restricted profiles — on stock Android it is Settings > System > Multiple users, then Add user or profile, then Restricted profile; on some tablets the path is Settings > Users & accounts > Users. One availability warning: this is a tablet feature. If the Multiple users menu is missing, or the only option under Add user or profile is Guest, the manufacturer has disabled restricted profiles, and this article's routes do not apply to your device. You also need a USB drive your tablet can read — a USB-C flash drive, or a regular USB drive with a USB-C OTG adapter (most modern Android tablets support OTG; if the tablet doesn't see the drive, try a different adapter) — and enough space on the drive for the photos you want to keep. One format note: drives formatted FAT32 can't hold a single file over 4 GB. That only matters for very long videos — SnapDisk skips those files and lists them instead of failing the whole backup. A drive formatted exFAT has no such limit.

Before any method, check which profile holds the photos, as above — the restricted-profile Gallery or the owner one. And one warning up front, because it applies to every route below: do the work while you are still in the restricted profile. The photos have to leave the profile before it is deleted — there is no after. The move has to happen inside the restricted-profile session, not after it is gone.

Method 1: copy inside the restricted profile, by hand

This is the route to try first, because it is the only one that needs no crossing between profiles and no cloud account. Everything happens inside the restricted profile: the photos start there, the copy happens there, and the drive is the destination. Switch into the restricted profile first — swipe down twice, tap the user icon, tap the restricted profile — then plug the USB drive into the tablet. Open the restricted profile's Files app and look for the USB drive under storage. If it appears, browse to the restricted-profile photos (in the profile Gallery, or Internal storage → DCIM → Camera inside the restricted profile), select them, tap Copy to, and choose the USB drive as the destination. Wait for the copy to finish before unplugging, and then verify it: plug the drive into another device and open a few photos, and confirm they render.

The honest limit of this route is the one stated in the TL;DR, and it is worth spelling out because it is the difference between a guide and a guess. Whether a USB drive plugged into the tablet appears in the restricted profile's Files app is unverified from Android's documentation: the developer docs confirm the profiles have separate storage areas, but they say nothing about whether a USB volume is visible per profile, and no source found for this article answers it either way. It may appear, and on many tablets it will — USB storage is device-wide hardware, not a per-profile folder — but that is an expectation, not a verified fact. So treat this method as a test, not a promise: plug the drive in, open the profile Files app, and look. If the drive is there, copy by hand and you are done. If it is not there, the route is closed on your tablet — do not keep tapping around hoping it appears — and the fallback is Method 2 or Method 3.

One more limit is specific to restricted profiles, and it comes from how the owner sets them up. The profile only shows the apps the owner explicitly allowed — by default most apps are off, and a hidden app cannot be launched in the profile. If the owner never enabled a file manager for the restricted profile, there may be no Files app to open inside it at all. The owner can fix that from the owner profile: Settings > System > Multiple users, tap the restricted profile, and toggle the file manager on. If the copy works, remember what it is: a manual copy. There is no oldest-first order, no progress bar with speed and time left, no Pause and Stop, and no resume if you unplug mid-copy. Copy in batches small enough to finish, check the count against what you selected, and open a few files on another device before you trust the drive. And the files on the drive are plain files — anyone who picks up the drive can open them — so if the photos are sensitive, this route protects nothing except against losing the tablet. Do the copy and the check before the profile is deleted: once it is gone, the photos are gone with it.

Method 2: move the photos to the owner profile before the profile is deleted

If the drive doesn't appear in the restricted profile, the next route is to move the photos across the boundary into the owner profile, where your personal apps — and SnapDisk — can see them. Do this while you are still in the restricted profile, before deleting it. There are two workable crossings. The first is a cloud account signed in inside the restricted profile: open Google Photos or Google Drive in the restricted profile, sign in with an account that belongs to the profile's user — not the owner's, or the point of the restricted profile is gone — upload the photos, wait for the upload to finish, and then check from another device or a browser that the photos are actually in the account. The second is sending the photos to yourself: from inside the restricted profile, share the photos by email or messaging to your own address, then open them in the owner profile and save them there. Once the photos are owner-profile files, Method 4 below backs them up to the USB drive with one tap.

The honest limit: the restricted-profile guides name no crossing at all — no "shared folder", no cloud advice, nothing. The guest-mode guides at least give one line — copy to a shared folder or cloud before deleting — but they name no owner-visible shared folder on stock Android, and the restricted-profile guides do not even go that far. So the cloud upload and the send-to-yourself are the crossings with named steps, because they are the only ones any guide describes with steps. A second limit is the account itself. A restricted profile starts with no Google account of its own; the guides say the profile's user can set one up when they first switch into it, and the owner decides which apps are visible, so whether a cloud app or an email app is even available inside the profile is the owner's call. If the profile never had an account signed in, the send-to-yourself route needs one too — an email app with no account cannot send mail. Check that before you count on either crossing.

Two things to know if the crossing works. First, the copy is a copy — the original stays in the restricted profile until the profile itself is removed, so you now have two copies, and the restricted-profile one is still at risk until the owner copy is verified. Second, check the moved copies before you rely on them: open a few in the owner Gallery and confirm they are the full photos, not thumbnails, and that videos play. A share that silently downscaled or truncated a file is worse than a share that failed loudly. And do the crossing before you delete the profile: there is no Keep-or-Remove prompt to save you, as there is when leaving a guest session — deleting the profile is the wipe, and it happens the moment the owner taps Delete.

Method 3: restricted-profile cloud as a bridge — not a USB backup

The third route goes through a cloud account that lives inside the restricted profile — Google Photos or Google Drive signed in with the profile user's account, in the restricted profile's instance of the app. Upload the photos from the profile app to that account, wait for the upload to finish, and then check from another device or a browser that the photos are actually in the account — a pending upload is not a verified copy, and a backup setting alone proves nothing. This gets the photos off the tablet, which is the urgent part when a profile deletion is coming.

Label this honestly: it is a fallback, not a USB backup. The photos leave the tablet to a profile account, not to a drive you hold, and getting them back after the profile is removed depends on keeping access to that account. The profile account is often a child's account, or one created on the spot for the profile — so keep the credentials available, because a cloud copy you cannot sign into is not a backup. And do not rely on standard Android device backup as the route: the restricted profile's local data is not part of the owner profile's device backup, and restoring a device backup does not bring a deleted restricted profile back.

If the cloud copy is verified and you can still reach the account, the photos can come back down to the owner profile — download them there, or open them on a computer and copy them to the USB drive directly — and then Method 4 handles the drive copy. But if the only copy of the photos is in a profile account you are about to lose, that is not a backup. It is a countdown. The USB drive is the copy that survives the profile ending; the cloud is the bridge that gets the photos there.

Method 5: installing SnapDisk inside the restricted profile

It sounds like the clean fix — put SnapDisk in the restricted profile, and it would see the restricted-profile photos the same way it sees owner ones. Do not plan a backup around it. SnapDisk is not on Google Play at all yet, so it cannot be installed from the Play Store in either profile — there is no listing for anyone to approve. On top of that, the restricted profile only shows the apps the owner explicitly allows, and a hidden app cannot be launched there — so even once SnapDisk is on Play, the owner would have to enable it for the profile first. The other way in is side-loading the APK inside the restricted profile, and that route is untested: no one has installed SnapDisk in a restricted profile, and no test has run there. And even if it installed, the profile is wiped when it is deleted — the app, its settings, and anything it had not yet copied would go with it — so the backup would have to finish before the deletion, with no second chance.

If SnapDisk is on Play one day, then SnapDisk inside the restricted profile would read the restricted profile's MediaStore and back up restricted-profile photos the same way it backs up owner ones today — oldest-first, size-verified, Pause and Stop, 5 GB free per run, Pro $9.99 once. But that is a conditional, not a claim: no one has installed SnapDisk in a restricted profile, and no test has run there. Until the Play listing exists, Method 5 is a request to make, not a backup to rely on.

Deleting the profile? Back up before it's removed

This is the sharpest motive for the whole article, and the one with the least room for error. Deleting a restricted profile deletes all of its local data: every photo the profile took, every file it downloaded, every app the owner enabled for it — gone, with no built-in way to restore them. The multi-user documentation is plain about the boundary: a profile does not exist beyond the lifetime of the user who created it, and removing a user "wipes all of that profile's apps, accounts, and files immediately, with no way to bring them back afterward". Unlike leaving a guest session, there is no Keep-or-Remove prompt on the way out — the owner opens Settings > System > Multiple users, taps the restricted profile, taps Delete, and the wipe is the deletion itself.

So the order matters, and it is not negotiable: back up first, verify the copy on another device second, delete the profile third. Open several photos from the drive on a computer and confirm they render; confirm the count matches what the restricted-profile Gallery showed. Only then delete the profile — or leave it in place if the child still uses the tablet. After deletion, check that the profile is gone as expected — and know what survives: nothing local does. The cloud copy survives only if you can still sign into the profile account, and the USB copy survives because you hold the drive. If the photos matter — a child's drawings on the family tablet, pictures that happen to live in the restricted-profile camera roll — the backup is the job, and the deletion is the deadline.

What to avoid

  • Assuming SnapDisk backs up restricted-profile photos. It cannot see them. An owner-profile app reads the owner profile's MediaStore, and the restricted-profile photos are in a different storage area. If the photos matter and they live in the restricted profile, Methods 1 to 3 are the routes — SnapDisk is the last step, not the first.
  • Trusting a green owner backup to have covered the restricted-profile photos. A backup that copied everything in the owner library copied zero restricted-profile photos. Check the count against what the restricted-profile Gallery shows before you call it done.
  • Deleting the profile before the crossing is done. There is no Keep-or-Remove prompt on the way out of a restricted profile — Delete is the wipe. Copy or upload first, delete second.
  • Assuming the drive appears in the restricted profile's Files app. Unverified from Android's documentation. Plug it in, look, and if it isn't there, move to Method 2 or 3 instead of tapping around hoping it appears.
  • Assuming the restricted profile has a file manager. The profile only shows the apps the owner allowed — by default most apps are off. If there is no Files app inside the profile, the owner has to enable it first.
  • Looking for this on a phone. Restricted profiles are a tablet (and TV) feature. If your phone has no Restricted profile option, this article does not apply — the guest-profile routes are the phone equivalent.
  • Counting on a "shared folder" that no guide names. The restricted-profile guides give no backup advice at all. The cloud upload and the send-to-yourself are the crossings with named steps — use those.
  • Treating a cloud upload as a USB backup. A profile-account cloud copy is a bridge, not a backup: it dies with that account if you lose access to it. The USB drive is the copy that survives the profile ending.
  • Signing the profile in with your own account. The profile can set up a Google account — but signing in with yours gives the profile your photos, messages, and app data, which is the thing a restricted profile exists to prevent. Use the profile user's own account.
  • Assuming the copy keeps running with the screen off. Unverified — no wake lock, no battery-saver handling in the repo — so keep the tablet awake for the run, or check it. Screen-off continuation under battery saver is unverified, and a run that stopped when the screen went dark is the expected failure, not a surprise.
  • Unplugging mid-copy. Pulling a USB drive out while files are still writing can corrupt the file in flight. Wait for the copy to finish, or pause it first — SnapDisk's Stop button exists for exactly this.

Rule of thumb: the profile is the boundary — the backup has to start inside the restricted profile, or the photos have to cross to the owner profile first. Check which profile holds the photos before you trust any backup, and back them up before the profile is removed, not after.
