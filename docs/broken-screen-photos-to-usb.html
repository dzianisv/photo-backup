Back up photos from a broken-screen phone to USB

A broken screen is three different problems, and only two of them have a phone-to-USB route at all: a cracked screen with dead touch, where you can still see the display; a black screen with the phone still powering on, where you cannot see anything; and a completely dead phone, where no software route exists. What you need

  • A broken-screen Android phone that still powers on — for the first two scenarios. If it does not power on at all, skip to the dead-phone part of Method 5: no method in this article reaches it.
  • A USB drive with enough free space — big enough for the whole photo library you want to copy, or enough room for the files you care about most. If the library is bigger than the drive, copy the year or the album you care about most first.
  • An OTG adapter, or a multi-port OTG hub. A single-port adapter holds either the mouse or the drive, not both — and a broken screen usually needs both at once. A hub with two or more USB-A ports solves it; a hub with HDMI as well solves the black-screen scenario too.
  • A wired USB mouse — any ordinary computer mouse works, wired or wireless with its dongle. This is what replaces your finger when touch is dead.
  • For a black screen: a monitor or TV with an HDMI input, an HDMI cable, and a USB-C hub with an HDMI port — and a phone that supports video-out, which is the part you have to check first, in Method 3.
  • Optional: a microSD card reader, for the card-removal route in Method 4 — but only if the phone takes a microSD card at all, and reading the card still needs a computer.
  • What the drive must not be: if the drive has no free space, or the phone cannot see it at all, no method below works — and if you want to keep the backup, do not buy a drive with no space to grow into. Drives formatted FAT32 cannot hold a single file over 4 GB, so a very long video will be skipped and listed, not copied — a drive formatted exFAT has no such limit.
  • What you should not buy: do not buy a single-port OTG adapter and expect to run a mouse and a drive off it at the same time; do not buy a USB-C hub for a micro-USB phone — the hub will not fit — and do not buy a cable and call it an adapter — a charging cable connects the phone to a computer, which is the opposite direction.

Three scenarios, and they shape which method to pick: first, a cracked screen with dead touch is the friendliest break — you can see the display, so a mouse replaces your finger and the backup is one tap away. Second, a black screen with the phone still on is the expensive break — you need video-out support and a hub before you can see anything at all, and most budget phones cannot do it. Third, a completely dead phone is not a backup problem any more — it is a repair problem, and the honest move is the cloud check, the card check, and then the repair shop.

Method 1: SnapDisk — cracked screen, dead touch

SnapDisk is the one-tap version, and a cracked screen with dead touch is the scenario it handles best — the display still works, so a mouse cursor does everything a finger did. It needs Android 7.0 or later, which is minSdk 24 in the repo, and it is not on Google Play yet, so install the v0.1.2 APK from the GitHub release page before the screen gets worse — or install it now, with the mouse, if the screen still shows the display.

  1. Plug the mouse into the phone through the OTG adapter or hub. A cursor appears on the display — that is your finger now.
  2. Use the mouse to enter your own PIN or pattern on the lock screen. A mouse does not bypass the lock — it only enters the code you already know — and if you cannot see the display at all, this step cannot happen, so go to Method 3 instead.
  3. Install SnapDisk v0.1.2 if it is not already on the phone — it is not on Google Play yet, so install the APK from the GitHub release page. You do not need an account, and there are no ads.
  4. Plug the USB drive into the phone — through the hub, so the mouse stays connected too. If you only have a single-port adapter, the mouse has to come out to make room for the drive — and then you cannot tap anything, unless Pro's auto-backup on connect was already set up, in which case plugging the drive in starts the backup by itself.
  5. Check the phone sees the drive before doing anything else. If nothing appears, the drive does not mount and neither this method nor Method 2 works on that phone.
  6. Tap Backup in the notification with the mouse. SnapDisk copies photos and videos oldest-first from the phone to the drive, in the background, with live progress, Pause and Stop.
  7. Wait for the copy to finish, then open a few photos on the drive before deleting anything from the phone.

Free version: backs up manually, up to 5 GB per run — one notification tap, which the mouse can do. Pro is a one-time $9.99 purchase — auto-backup on connect and unlimited size — and it is the hands-free route here: with Pro set up, plugging the drive in starts the backup with no tap at all, so the mouse can come out and the single-port problem goes away. But Pro only helps if it was set up before the screen broke — you cannot buy and enable it with a dead touch and no mouse, and you cannot enable it at all if you cannot see the display. On a phone that still shows its display, the one-tap backup works — the mouse replaces the finger, and the notification tap is the only tap the backup needs.

Method 2: file manager + OTG mouse

Same plug, no app to install. This is the manual version of Method 1, and it is the route the repair-shop guide describes — an OTG mouse, your own PIN or pattern, then a copy to the USB drive:

  1. Plug the mouse into the phone through the OTG adapter or hub, and use it to enter your own PIN or pattern. A mouse does not bypass the lock.
  2. Plug the USB drive into the phone through the hub — or swap the mouse out for the drive if you only have a single-port adapter, and only if you can already see the file manager open on the screen, because without the mouse you cannot tap anything else.
  3. Check the phone sees the drive. If nothing appears, the drive does not mount and this method does not work on that phone.
  4. Open the phone's file manager with the mouse and find the DCIM folder — that is where the camera photos live.
  5. Select the photos and videos, copy them to the USB drive, and wait for the copy to finish.
  6. Open a few photos on the drive before deleting anything from the phone.

The file-manager copy works on any Android phone that hosts USB OTG, with no version floor at all — it is the route when SnapDisk cannot install, because the phone runs below Android 7.0. What it does not give you is the one-tap backup: no oldest-first order, no progress bar with speed and ETA, no Pause and Stop, and no resume if you unplug mid-copy. And the single-port trap bites harder here than in Method 1 — without Pro's auto-backup, every tap needs the mouse, so a hub with two USB ports is not optional, it is the whole method.

Method 3: black screen — a USB-C video-out hub

If the screen is black but the phone still powers on — you hear sounds, feel vibrations, the charging light comes on — the display is the problem, not the phone, and a USB-C hub with an HDMI port lets you see the screen on a monitor instead. But this only works if the phone supports video-out, and most phones do not.

  1. Check whether your phone supports video-out before buying a hub. Video-out needs DisplayPort Alt Mode over USB-C — a USB 2.0 port physically cannot carry video, and most budget phones lack it entirely.
  2. Plug the hub into the phone, the HDMI cable into the hub and the monitor, and the mouse into the hub's USB port. The phone's screen should appear on the monitor — as a mirror, or as a desktop if the phone offers one.
  3. Use the mouse on the monitor to enter your own PIN or pattern. If the phone shows an on-screen prompt asking to allow video-out, and you cannot see or tap it, the hub route stops here — that prompt is the block the repair-shop guide warns about.
  4. Plug the USB drive into the hub's second USB port, then tap Backup in SnapDisk's notification with the mouse. SnapDisk copies oldest-first, with progress, Pause and Stop.
  5. Wait for the copy to finish, then open a few photos on the drive before deleting anything from the phone.

Which phones support video-out, from the lists: Samsung DeX runs on the Galaxy S8 and later S series, the Note 8 and later, all Z Fold models and the A90 5G only — Samsung's own adapter page lists the S8 through S24 series, the Note 8 through Note 20 series, the Z Fold series and the Tab S4 and later — while the Z Flip 5 and 6 output video but run no DeX, per XDA, and the rest of the A series outputs nothing at all. Google Pixel video-out starts at the Pixel 8 — the Pixel 6 and 7 have USB 3.x ports but Google left display output switched off until the Pixel 8 — and Android 16's native desktop mode, which turns the mirrored screen into a desktop with a taskbar, needs Android 16 QPR3 or later on a Pixel 8, 9 or 10, per Rayneo, so an older Pixel mirrors instead. Motorola Edge phones run Ready For, now Smart Connect; Huawei Mate and P Pro phones run Easy Projection; Sony's Xperia 1 and 5 series, Asus ROG Phones, the LG G8, V50, V60, Velvet and Wing, and the Fairphone 5 are listed as supporting video-out too. OnePlus is contested — the 12, 13 and Open per the usbctohdmi guide, against the 7 and newer flagships per the salivity list — so check your exact model before buying a hub. Generally not supported: the Galaxy A series except the A90 5G, the Pixel 7 and every earlier Pixel, most Redmi, POCO and Realme phones, most Moto G phones, Nothing phones, and almost anything sold as a budget or entry-level phone. One reported workaround for phones without video-out is a DisplayLink dock, which renders video over plain USB — Faceofit names it as the only way an older Pixel 7 can output to a monitor — but that is a paid dongle and a workaround, not native video-out, and it is carried here as reported, not verified. If your phone is not on any video-out list, the hub will show nothing, and the realistic step is a screen replacement — once the display works again, you can unlock the phone normally and copy everything off, which is exactly why a repair often comes before the recovery itself.

Method 4: microSD card removal route

If the phone takes a microSD card — and most high-end phones no longer do, per Android Authority — the card is the backup, and the reader is the bridge:

  1. Take the microSD card out of the phone. This needs no working screen at all — it is the one route in this article that works even on a completely dead phone, as long as the photos were stored on the card.
  2. Put the card in a card reader, plug the reader into a computer, and copy the photos from the card to the USB drive.
  3. Open a few photos on the drive before deleting anything from the phone.

Two honest limits. First, this only works if the photos are actually on the card — on most Android phones the camera saves to internal storage by default, so the card may hold nothing at all, and Android does not use external storage for many critical files. Second, it is not a no-computer route: reading the card needs a reader and a computer, so it breaks the premise of this article — it is here because it is the only route that survives a completely dead phone. If the phone has no card slot, there is no Method 4.

Method 5: Google Photos, or the cloud

The cloud is the check that comes before all the hardware — and the one every guide in the results names first. Google Photos may already hold the whole library, and checking it needs no working phone at all.

  1. On another device — a computer, a friend's phone — open Google Photos and look at the library. If the photos are there, they are already safe, and the broken phone is a repair problem, not a backup emergency.
  2. If recent photos are missing, the cloud backup was off or behind, and the hardware routes above are what is left.
  3. If the library is complete in the cloud and you still want a USB copy, download the photos on a computer and copy them to the USB drive — which needs the computer, so it is the fallback, not the route, when the phone and the drive are all you have.

Two warnings. First, Google Photos' "Storage saver" setting compresses photos, which is the one place quality actually gets lost — check the setting before trusting a cloud copy. Second, a cloud backup is not a USB backup: your photos sit on Google's servers, and the backup stops working the day you stop paying for storage. If you want to plug the drive into a computer and open the pictures, you need a plain copy — that is Method 1 or 2, not a cloud backup. And for a completely dead phone, the cloud check and the card check are the only two moves that need no working phone at all — if neither holds the photos, Android Authority's answer stands: replace the faulty components, or seek help from a data recovery professional.

What this does not do

  • Does not unlock your phone. A mouse, a hub and a monitor only let you enter the PIN or pattern you already know. Nothing in this article bypasses a screen lock, and no app can — if you do not know the code, the backup cannot start.
  • Does not install below Android 7.0. SnapDisk needs Android 7.0 or later — minSdk 24 in the repo — so on a phone running older Android, use Method 2 instead: the file-manager copy has no version floor.
  • Does not work on a completely dead phone. If the phone does not power on at all, no app, adapter or hub can reach its storage. Check Google Photos and the microSD card, then a screen replacement or professional recovery.
  • Does not work if the phone has no video-out and no visible screen. A black screen with no DisplayPort Alt Mode leaves no way to see the phone's display — the hub shows nothing, the mouse has nothing to click, and the backup cannot start.
  • Does not work if the phone does not host a drive. The phone has to support USB OTG to see the drive at all. Most Android phones do, but a phone that lists OTG No cannot mount a drive, and then neither the one-tap backup nor the file-manager copy works on it.
  • Does not copy files over 4 GB off a FAT32 drive. Drives formatted FAT32 cannot hold a single file over 4 GB — SnapDisk skips those files and lists them instead of failing the whole backup, per the repo README. A drive formatted exFAT has no such limit.
  • Does not delete photos. SnapDisk only copies — it never deletes — so the delete step is always yours, and always after the check.
  • Does not back up anything but photos and videos. SnapDisk copies image and video files only — no settings, no contacts, no messages, no app data.
  • Does not back up photos from apps that hide them. If an app keeps its photos in a private folder SnapDisk cannot read, those photos stay in the app.
  • Does not compress. SnapDisk copies the original files as they are — no recompression, no resizing, no quality loss.

What to avoid

  • Buying a single-port adapter when you need a mouse and a drive. One port holds either the mouse or the drive, not both. A multi-port OTG hub is the fix — or Pro's auto-backup on connect, if it was set up before the screen broke, which starts the backup the moment the drive goes in.
  • Buying a USB-C hub for a micro-USB phone. The hub will not fit. Check the port before buying anything — a USB-C hub is the wrong adapter for a micro-USB phone, and a micro-USB OTG adapter is the wrong adapter for a USB-C phone.
  • Assuming your phone does video-out. Most phones do not. A USB 2.0 port physically cannot carry video, and most budget phones lack DisplayPort Alt Mode entirely — check your exact model against a video-out list before buying a hub, or the hub will show nothing.
  • Trusting one video-out list. OnePlus video-out is two claims — the 12, 13 and Open per the usbctohdmi guide, against the 7 and newer flagships per the salivity list — and the Miracast.org list downgrades single-source entries to disputed rather than counting them as confirmed, so check the exact model, not the brand.
  • Mistaking a recovery app for a backup. Dr.Fone and Recoverit are recovery tools, not backups: they run on a computer, they cost money, and they extract files after the damage — they do not copy your whole library to a drive you can keep with one tap. A backup is a plain copy on a drive; a recovery tool is the ambulance after the crash.
  • Mistaking screen mirroring for a desktop. A mirrored screen shows the phone's display on the monitor — a desktop mode like DeX or Android 16's native desktop gives you windows and a taskbar. Either one lets you tap Backup, but only the phones named in Method 3 open a desktop at all.
  • Paying for professional recovery before checking the cloud and the card. Google Photos on another device and the microSD card out through a reader are free, and either one may already hold the photos. Professional recovery is the last resort, not the first call — and Android Authority names it only for a completely dead phone.
  • Factory resetting, flashing firmware, or approving a wipe repair before the backup. Recoverit warns against it plainly: do not factory reset, flash firmware, or approve any repair that wipes the phone before you have tried the safer options. A wipe deletes the photos you are trying to save.
  • Mistaking a cloud backup for a photo copy. Google Photos backs your phone up to Google's servers — if you want to plug the drive into a computer and open the pictures, you need a plain copy, that is Method 1 or 2, not a cloud backup. And Google Photos' "Storage saver" setting compresses photos, which is the one place quality actually gets lost.
  • Mistaking a PC tool for a phone-to-USB copy. A computer copy with a USB cable moves files to a computer — but it is a copy to a computer, and the backup lands on the PC. If the phone and the drive are all you have, a phone-to-USB copy is the route, not a desktop copy.
  • Deleting before verifying. A backup is only a backup once you've confirmed the copy. Copy, open a few photos on the drive, then delete from the phone — never the other way round. SnapDisk only copies — it never deletes — so the delete step is always yours, and always after the check.
  • Moving instead of copying. The file manager's Move option copies and then deletes the originals in one step. If the copy fails halfway, photos are already gone from the phone. Copy first, verify, then delete.
  • Unplugging mid-copy. Pulling a USB drive out while files are still writing can corrupt the file in flight. Wait for the copy to finish, or pause it first — SnapDisk's Stop button exists for exactly this.
  • Forgetting the phone cannot charge while the mouse occupies its only port. The repair-shop guide warns about it: a phone with one port cannot charge while the mouse is plugged in, so plan the transfer before you unplug anything — and start with a charged phone, because a dead battery mid-copy ends the backup.

Rule of thumb: cracked screen, dead touch, display still visible — a mouse and one tap; black screen, phone still on — a video-out hub and a mouse, and only on phones that support it; completely dead — no software route, check the cloud and the card, then repair. A mouse never bypasses the lock, one port never holds both mouse and drive, and a hub never shows a picture on a phone without video-out.
