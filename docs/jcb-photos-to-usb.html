Method 1: SnapDisk (one tap, background copy)

SnapDisk is a free Android app that does exactly this job and nothing else. Install it from the v0.1.2 APK (it's not on Google Play yet), then:

  1. Plug in the USB drive. It mounts on plug-in on most Android phones with USB host support — look for a "USB storage added" notification. If nothing appears, check Settings > Storage for the drive. Every current model runs Android 7.0 or later, so SnapDisk installs on any of them.
  2. Open SnapDisk and check the folders. The app opens to a settings screen with a From folder and a To folder, each with a folder picker. The defaults are already right for most people: From /sdcard/DCIM (your camera photos — JCB Toughphone camera photos live in DCIM/Camera), To /disk/DCIM on the drive. If your photos live somewhere else, tap the From picker and choose that folder — the picker is the Android system folder picker, and the app keeps access to it.
  3. Tap Backup. SnapDisk offers a backup in a notification when the drive connects: "External storage is connected. Backup photos?" Tap it and your whole library copies oldest-first — your earliest photos first — in the background, while you use the phone normally. The copy mirrors the source folder structure on the drive, so DCIM stays DCIM.
  4. Watch the progress notification — real percent, copied / total size, speed, and time left — with Pause and Stop. You can pause and resume any time.
  5. Wait for "Backup complete." Every file is size-verified after copying, so the counts are proof, not a promise. Files that already copied are never copied twice — so if the free 5 GB per-run limit stops a big library partway, just run it again and it picks up where it left off.

The copies are the original files. SnapDisk streams each file byte-for-byte from the phone to the drive — the code reads the file and writes the same bytes out, with no decode, no recompression, and no resize — and then checks that the copy on the drive is the same size as the original. Other apps copy originals byte-for-byte too; what SnapDisk adds is the automated whole-library run: oldest-first order, progress with Pause and Stop, resume where it stopped, and skip-if-already-copied on the next run. If a file is corrupt or too big for FAT32, it's retried once, then skipped with its reason listed — it never stalls the whole backup. The free version backs up manually, up to 5 GB per backup run, with no ads, no account, and no cloud. SnapDisk Pro is a one-time $9.99 purchase (no subscription) that starts the backup automatically when you plug in a disk and removes the size limit. The app has no internet permission, so your photos physically cannot leave your device.

Method 2: a file manager (the stock route, no app needed)

A file manager can copy your photos to the USB drive — the YouTube guides' route is an OTG connection with the built-in file manager, and the Android Central forum's route is the same, and either is the manual route for external storage: 1. Plug in the USB drive — a notification should appear saying "USB storage added"; tap it to open the drive. If nothing appears, check Settings > Storage for the drive. 2. Open the file manager (Files by Google on JCB Toughphone phones) and confirm the USB drive shows up under storage devices. 3. Go back to Internal storage, DCIM, Camera, where your camera photos live. 4. Select the photos (long-press the first, tap the rest, or select all). 5. Tap Copy, then select the USB drive, and wait for the copy to finish — don't unplug the drive until the file manager says it's done. Eject the drive from the notification or from Settings > Storage before unplugging it. Use Copy, not Move: Move deletes the originals as it goes, so a bumped cable halfway through loses photos. This works fine for a one-off copy. Its limits are the reason SnapDisk exists: you pick files one by one, there is no progress detail beyond a spinner, no resume if you unplug mid-copy, no verification that every file actually arrived, and you have to repeat the whole manual selection next time photos pile up. For a library that grows every day, the app's oldest-first background copy is the calmer option.

What this does not do

A few honest limits, so the automatic copy is not oversold:

  • Photos and videos only. SnapDisk copies image and video files. Documents, voice notes, and anything that isn't a photo or video is skipped — Google backup is the tool if you want contacts, messages, and settings in the same backup, not just photos.
  • Only the folder you pick. By default that's DCIM — your camera photos. Photos in other folders (Downloads, app folders) only copy if you point the From folder at them, or at a parent folder that contains them.
  • Free 5 GB per run. A library bigger than 5 GB stops at the cap; run it again and it picks up where it stopped. Pro ($9.99, one-time) removes the limit and starts the backup automatically when you plug in a disk.
  • Files over 4 GB on FAT32 are skipped. Very long videos on a FAT32 drive are listed with their reason instead of failing the backup. Reformat the drive to exFAT if you need them.
  • It never deletes. SnapDisk only copies. Freeing space on the phone is copy, check the copy on the drive, then delete the originals yourself — never the other way round.
  • OTG support is unconfirmed on the E50. The Toughphone, the Toughphone Max, the E10, and the T10 all list OTG support — cashify lists "OTG Support, Yes" for the Toughphone and the Toughphone Max, the E10 review lists "USB-C 2.0 (OTG)", and JCB's own T10 page lists "USB-C with OTG support" — but no source I found mentions OTG on the E50 at all, so plug a drive in and check Settings > Storage on that model before relying on it. The drive mounting is the test.
  • The E10's specs are disputed between sources. One review's own spec table says Android 16 while its text and JCB's own site say Android 15; the same review says the chipset is a Helio G36, while Clove and rugged.co.uk say MT6765X; and the review says 4 GB of RAM while rugged.co.uk says 8 GB. The Android version is taken as 15 from JCB's own site, and the chipset and RAM are not leaned on here. Either way the E10 clears SnapDisk's Android 7.0 minimum.
  • Two old JCB phones cannot run SnapDisk at all. The TP802 is a feature phone, not an Android phone, and the Toughphone Pro-Smart TP909 from 2012 runs Android 2.3.5 Gingerbread — both are below SnapDisk's Android 7.0 minimum. On those phones the computer copy in Method 4 is the route.
  • All current models have USB-C, so the adapter is the same either way. The Toughphone, the Toughphone Max, the E10, the E50, and the T10 tablet all have a USB Type-C port, so a USB-C flash drive plugs straight into any of them and a regular USB-A drive needs a USB-C OTG adapter on any of them. A plain USB-C charging cable is not an OTG adapter: it connects the phone to a computer, which is the opposite direction.

What to avoid

  • Buying an adapter you don't need — or the wrong one. A USB-C flash drive plugs straight into any current JCB model, all of which have USB-C — so an adapter is only needed for a regular USB-A drive, and it must be a USB-C OTG adapter, not a micro-USB one. A plain USB-C charging cable is not an OTG adapter: it connects the phone to a computer, which is the opposite direction.
  • Mistaking a cloud backup for a photo copy. Google Drive and Google Photos back your phone up to Google's servers — if you want to plug the drive into a computer and open the pictures, you need a plain copy, that is Method 1 or 2, not a cloud backup.
  • Mistaking a PC tool for a phone-to-USB copy. JCB's own file advice is a computer copy with a USB cable — but it is a copy to a computer, and the backup lands on the PC. If the phone and the drive are all you have, a phone-to-USB copy is the route, not a desktop copy.
  • Mistaking a spec table or a manual page for a phone-to-USB guide. The TP802 manual and the JCB Toughphone spec pages are real JCB pages — but the manual only says to connect to a PC with a USB cable and copy files as Mass Storage, and the spec pages only list an Android version, a chipset, or a USB connector type. Neither of them describes copying your camera roll straight to a USB drive from the phone.
  • Mistaking OTG support on one model for OTG support on the other. The Toughphone, the Toughphone Max, the E10, and the T10 all list OTG support — cashify lists "OTG Support, Yes" for the Toughphone and the Toughphone Max, the E10 review lists "USB-C 2.0 (OTG)", and JCB's own T10 page lists "USB-C with OTG support" — but no source I found mentions OTG on the E50. Test with a drive on the E50, and use Method 2 or 4 on that model if the drive never mounts.
  • Mistaking a microSD card copy for a USB backup. Copying DCIM to a microSD card is a real local copy — every current JCB model takes a microSD card — but the card stays in the phone, and opening it anywhere else needs a card reader; a USB drive plugs into any computer as it is.
  • PC-only tools when you have no computer. Drag-and-drop through a Windows PC works — but it needs the PC in between. If the phone and the drive are all you have, a phone-to-USB copy is the route — that is the gap this article fills, as of November 18, 2026.
  • Cloud backup dressed as USB backup. If the app needs an account and an upload before your photos are safe, that's a cloud subscription with a USB step. Your photos sit on someone else's server, and the backup stops working the day you stop paying. On a JCB Toughphone the cloud routes are Google Photos and Google Drive — and Google Photos' "Storage saver" setting compresses photos, which is the one place quality actually gets lost.
  • Deleting before verifying. A backup is only a backup once you've confirmed the copy. Copy, open a few photos on the drive, then delete from the phone — never the other way round. SnapDisk only copies — it never deletes — so the delete step is always yours, and always after the check.
  • Moving instead of copying. The file manager's Move option copies and then deletes the originals in one step. If the copy fails halfway, photos are already gone from the phone. Copy first, verify, then delete.
  • Unplugging mid-copy. Pulling a USB drive out while files are still writing can corrupt the file in flight. Wait for the copy to finish, or pause it first — SnapDisk's Stop button exists for exactly this.

Rule of thumb: if you have to pick the files yourself, it isn't a backup — it's a chore you will skip. Automate the copy, check it on the drive, then delete from the phone.
